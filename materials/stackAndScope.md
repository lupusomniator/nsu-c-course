# Стековые кадры, области видимости и время хранения

## 1. У каждого вызова — свои локальные переменные

Начнём с двух функций:

```c
#include <stdio.h>

int AddOne(int value) {
    int result = value + 1;
    return result;
}

int main(void) {
    int value = 10;
    int result = AddOne(value);
    printf("%d %d\n", value, result); // 10 11
    return 0;
}
```

В программе два имени `value` и два имени `result`. Но это разные объекты.
Параметр `value` функции `AddOne` получает копию числа 10. Локальный `result`
этой функции получает 11, и это значение возвращается вызывающему коду.
Уже затем оно записывается в `result` функции `main`.

Пока работает `AddOne`, выполнение `main` приостановлено, но её переменные
продолжают существовать. После возврата `main` должна продолжить работу
со своими значениями.

Типичная реализация решает эту задачу с помощью **стека вызовов**.
С каждым активным вызовом связывают **стековый кадр**, или **стекфрейм**:
область для данных, нужных этому вызову. Там могут находиться локальные
объекты, сохранённые регистры и сведения для возврата. Часть аргументов
и адрес возврата могут передаваться в регистрах — это зависит от платформы.

Во время выполнения `AddOne` картину можно представить так:

```text
Активный вызов      Его данные в нашей модели
┌──────────────────────────────────────────────┐
│ AddOne: value = 10, result = 11              │ <- выполняется сейчас
│ вернуться в main после вызова AddOne         │
├──────────────────────────────────────────────┤
│ main: value = 10                             │ <- ждёт возврата
│ инициализация result ещё не завершена        │
└──────────────────────────────────────────────┘
```

Когда `AddOne` заканчивается, её кадр больше не нужен. Управление возвращается
в `main`, а результат вызова становится значением её переменной `result`.
При следующем вызове `AddOne` появятся новые экземпляры её обычных локальных
переменных, даже если для них будет использована та же память.

**Это модель распространённой реализации, а не требование языка C.**
Компилятор может хранить значение в регистре, встроить функцию или полностью
убрать вычисление. Стандарт задаёт поведение объектов, но не требует, чтобы
каждому из них соответствовала ячейка на стеке. Схема также не задаёт направление
роста адресов памяти.

## 2. Рекурсия: одна функция, несколько активных вызовов

Если бы у функции был один общий набор локальных переменных, рекурсия
перезаписывала бы результаты предыдущего вызова. Посмотрим на пример:

```c
int SumTo(int n) {
    if (n == 0) {
        return 0;
    }
    int rest = SumTo(n - 1);
    return n + rest;
}
```

Для маленьких неотрицательных `n` функция суммирует числа от 1 до `n`.
Вызов `SumTo(3)` создаёт цепочку:

```text
main ждёт SumTo(3)
    SumTo(3): своё n = 3, ждёт SumTo(2)
        SumTo(2): своё n = 2, ждёт SumTo(1)
            SumTo(1): своё n = 1, ждёт SumTo(0)
                SumTo(0): своё n = 0, возвращает 0
```

Вызовы завершаются в обратном порядке. `SumTo(1)` получает 0 и возвращает 1,
`SumTo(2)` получает 1 и возвращает 3, `SumTo(3)` получает 3 и возвращает 6.
У каждого вызова своё `n`; оно не превратилось в ноль из-за последнего вызова.

В обычной реализации глубокая рекурсия расходует стек на множество кадров.
Стек ограничен, поэтому даже маленькие локальные объекты не делают
неограниченную рекурсию безопасной. Оптимизация иногда убирает кадры,
но рассчитывать на это для корректности программы нельзя.
Полный пример: [stackFrames.c]({{ '/materials/examples/stackFrames.c' | relative_url }}).

## 3. Область видимости: где имя обозначает объект

Теперь зададим другой вопрос: где в тексте программы можно написать имя
переменной и обратиться к ней? Это **область видимости**.

```c
int score = 10;

{
    int bonus = 5;
    printf("%d\n", score + bonus); // 15
}

printf("%d\n", score);            // 10
// printf("%d\n", bonus);         // Ошибка: имя bonus здесь недоступно.
```

Фрагмент предназначен для тела функции. Внутренний блок видит внешнее имя
`score`. Имя `bonus` доступно только внутри своего блока, начиная с объявления.
Закрывающая скобка заканчивает эту область видимости.

Можно объявить во внутреннем блоке такое же имя:

```c
int value = 10;

{
    int value = 20;
    value += 1;
    printf("%d\n", value); // 21: внутренний объект.
}

printf("%d\n", value);     // 10: внешний объект не изменился.
```

Внутреннее объявление **скрывает** внешнее. Оно не сохраняет старое значение
с последующим восстановлением: в программе изначально два объекта.
Внешний объект продолжает жить, просто внутри блока имя `value` обозначает
другой объект. В рабочем коде лучше выбирать разные имена, если такое
скрытие затрудняет чтение.

Отдельные фигурные скобки **не означают отдельный стековый кадр**.
Вложенный блок — часть вызова той же функции. Компилятор может заранее
отвести место для его переменных в кадре и переиспользовать это место,
когда время жизни объектов закончится.

### Вызываемая функция не наследует имена вызывающей

```c
void PrintValue(void) {
    // printf("%d\n", value); // Ошибка: здесь нет объявления value.
}

int main(void) {
    int value = 10;
    PrintValue();
    return 0;
}
```

Наличие `value` в активном вызове `main` не делает имя доступным в `PrintValue`.
Области видимости определяются расположением объявлений в исходном коде,
а не текущей цепочкой вызовов. Чтобы передать данные, задайте параметр:
`void PrintValue(int value)` — и вызовите `PrintValue(value)`.

Имена, объявленные вне функций, имеют область видимости файла: они доступны
от своего объявления до конца файла, кроме участков, где скрыты другим
объявлением. Видимость в исходном коде не следует путать со связыванием
объявлений между разными `.c` — это отдельная тема.

## 4. Время хранения: когда объект существует

Область видимости относится к **имени в тексте**, а время хранения —
к **объекту при выполнении**. На обычных локальных переменных границы часто
выглядят похоже, поэтому их легко смешать. Локальный `static` покажет разницу:

```c
void CountCalls(void) {
    int current = 0;
    static int total = 0;

    ++current;
    ++total;
    printf("current=%d total=%d\n", current, total);
}
```

Вызовем функцию три раза:

```c
CountCalls(); // current=1 total=1
CountCalls(); // current=1 total=2
CountCalls(); // current=1 total=3
```

`current` имеет **автоматическое время хранения**. Каждый вызов получает
новый объект и выполняет его инициализацию нулём. Когда функция возвращается,
время жизни этого объекта заканчивается.

`total` имеет **статическое время хранения**: это один объект, существующий
всё выполнение программы. В C его начальная инициализация происходит
до запуска программы, а не при каждом входе в функцию. Вызовы используют
этот же объект и постепенно увеличивают его значение.

При этом имя `total` по-прежнему доступно только внутри `CountCalls`.
Из `main` нельзя написать `printf("%d", total)`. Объект существует,
но имя в этом месте недоступно.

| Объявление | Где доступно имя | Сколько живёт объект |
| --- | --- | --- |
| `int value;` внутри блока | От объявления до конца блока, кроме участков скрытия | В пределах соответствующего выполнения блока |
| `static int value;` внутри блока | Та же блочная область видимости | Всё выполнение программы |
| `int value;` вне функций | От объявления до конца файла, кроме участков скрытия | Всё выполнение программы |

У обычного локального объекта без инициализатора нет гарантированного
начального значения. У объекта со статическим временем хранения без явного
инициализатора значения обнуляются. Для `static int total;` результат
будет тем же, что для `static int total = 0;`.

## 5. Указатель не продлевает время жизни

Можно передать адрес локальной переменной другой функции:

```c
void Increment(int* value) {
    ++*value;
}

int main(void) {
    int count = 10;
    Increment(&count);
    printf("%d\n", count); // 11
    return 0;
}
```

Пока работает `Increment`, объект `count` в `main` жив. Имя `count`
вызываемой функции неизвестно, но она получила адрес объекта и может его
изменить. Видимость имени для этого не требуется.

А возвращать адрес собственного обычного локального объекта нельзя:

```c
// Намеренно ошибочная функция.
int* MakeValue(void) {
    int value = 42;
    return &value;
}
```

После возврата объект `value` больше не существует. Разыменование полученного
указателя имеет неопределённое поведение. То, что по старому адресу некоторое
время могут оставаться прежние байты, не делает доступ допустимым.
Для одного числа достаточно вернуть значение: `int MakeValue(void) { return 42; }`.

Добавление `static` действительно продлило бы время жизни объекта, но изменило
бы смысл функции: все вызовы обращались бы к одному общему объекту.
Это не способ автоматически получить новый независимый результат каждого вызова.

## 6. Массив фиксированного размера и `static` — разные признаки

Словом "статический" иногда нестрого называют любой массив с заранее известным
размером. В C это сбивает с толку: ключевое слово `static` говорит о времени
хранения локального объекта, а не просто о записи размера числом.

```c
void Work(void) {
    int temporary[10] = {0};
    static int saved[10] = {0};

    ++temporary[0];
    ++saved[0];
    printf("%d %d\n", temporary[0], saved[0]);
}
```

Оба массива содержат ровно 10 элементов, и **оба объявления разрешены**.
Первый вызов `Work()` напечатает `1 1`, второй — `1 2`.
`temporary` создаётся заново для вызова, а `saved` сохраняет данные между
вызовами. В типичной реализации `temporary` может лежать в кадре вызова,
а `saved` размещается отдельно, в области статических данных.

Большой `temporary` может исчерпать стек, но компилятор не обязан запрещать
его объявление. Это отдельная проблема ресурсов, не причина запрета
`static int values[n]`.

## 7. Когда размер становится известен при выполнении

Пусть количество элементов передаётся в функцию:

```c
void PrintLast(int n) {
    if (n <= 0 || n > 100) {
        return;
    }

    int values[n]; // VLA: variable-length array.
    for (int i = 0; i < n; ++i) {
        values[i] = i + 1;
    }
    printf("%d\n", values[n - 1]);
}
```

`PrintLast(3)` создаёт массив из трёх элементов и выводит 3,
`PrintLast(5)` — массив из пяти элементов и выводит 5.
Размер вычисляется при прохождении объявления. Для каждого созданного
массива он затем остаётся прежним: изменение `n` не меняет длину уже
существующего массива.

Такой массив называется **VLA**, массивом переменной длины. Его время жизни
начинается при выполнении объявления и заканчивается при выходе из области
видимости. В обычной реализации компилятор может запросить место на стеке
во время выполнения: размер кадра не обязан быть целиком известен заранее,
однако он должен быть ограниченного размера - поэтому на такой n компилятор сам наклывадет ограничение. Можно попытаться создать **VLA** огромной длины, но из-за
ограничениия длины стекфрейма объекты в хвосте будут попросту недоступны.

```c
PrintLast(1000000000);
```

Помните, что **VLA** это в общем случае плохо, и его нужно избегать.

См. [документацию GCC о VLA](https://gcc.gnu.org/onlinedocs/gcc/Variable-Length.html).

Размер должен быть положительным; слишком большой размер опасен для стека.
Здесь мы ограничили его сотней элементов. В C17 нельзя написать
`int values[n] = {0};` для VLA: элементы нужно заполнить отдельно.

**Поддержка VLA в C17 необязательна.** GCC и Clang их поддерживают,
а MSVC — нет. Поэтому отказ MSVC от `int values[n]` не означает,
что все компиляторы C обязаны отвергать такой код.
См. [режимы стандартов MSVC](https://learn.microsoft.com/en-us/cpp/build/reference/std-specify-language-standard-version).
Запускаемый пример для GCC / Clang: [variableArray.c]({{ '/materials/examples/variableArray.c' | relative_url }}).

## 8. Почему нельзя `static int values[n]`

Теперь объединим две идеи:

```c
// Ошибка в C17: массив переменной длины со статическим временем хранения.
void Remember(int n) {
    static int values[n];
}
```

У обычного VLA есть конкретное выполнение объявления, в котором берётся
текущее `n`, создаётся массив нужной длины, а затем этот массив прекращает
существовать при выходе из блока.

У локального `static` другая модель: **один объект на всё выполнение программы**.
Его размер не выбирается заново при каждом вызове. Представим вызовы:

```c
Remember(3);
Remember(100);
```

Какая длина должна быть у единственного массива — 3 или 100? Нужно ли менять
её при втором вызове? Что тогда делать с сохранёнными элементами и ранее
полученными указателями? Можно придумать разные правила, но C не задаёт
ни "выбрать длину при первом вызове", ни "перевыделять при каждом вызове"
для локального `static`.

Правило C17 прямо запрещает объекту VLA иметь статическое время хранения.
Для такого массива нужен размер, заданный **целочисленным константным
выражением**. Это ограничение языка, согласованное с моделью хранения,
а не неспособность компьютера в принципе выделить память во время выполнения.

Размер можно задать числом, элементом `enum` или подходящим макросом:

```c
enum { CAPACITY = 100 };

void Remember(void) {
    static int values[CAPACITY]; // Разрешено: один массив из 100 элементов.
    ++values[0];
    printf("%d\n", values[0]);
}
```

Первый вызов выводит 1, второй — 2. Размер определён независимо от вызовов,
а содержимое сохраняется между ними.

### Почему `const int` не помогает

```c
void Work(void) {
    const int n = 10;
    static int values[n]; // Не является переносимым объявлением в C17.
}
```

Человеку видно, что `n` равно 10 и его нельзя изменять. Однако в C17 `const`
означает запрет изменения объекта через это имя, а не превращение имени
в целочисленное константное выражение. Способность оптимизатора вычислить
значение заранее не меняет этого правила языка.

Для переносимого кода замените `const int n = 10;` на
`enum { N = 10 };`, а размер — на `N`. Макрос `#define N 10` также подходит:
после препроцессора в объявлении будет число 10.
Некоторые компиляторы принимают вариант с `const` как расширение;
это не делает его переносимым C17. Не переносите сюда правила C++.

Та же проблема возникает вне функций:

```c
int n = 10;
int values[n]; // Ошибка: такой массив нельзя объявить на уровне файла.
```

Объект `values` здесь и без слова `static` имел бы статическое время хранения.
Кроме того, вариативно модифицированные типы не допускаются в области файла.

## 9. Что выбрать вместо запрещённого объявления

Если есть небольшая известная верхняя граница, разделите **вместимость**
и **число используемых элементов**:

```c
enum { CAPACITY = 100 };

void Process(int n) {
    if (n <= 0 || n > CAPACITY) {
        return;
    }

    int values[CAPACITY];
    for (int i = 0; i < n; ++i) {
        values[i] = i + 1;
    }
    printf("%d\n", values[n - 1]);
}
```

Место есть для 100 элементов, но функция использует только первые `n`.
Остальные элементы не инициализированы, и читать их здесь не нужно.
Такой код работает и без поддержки VLA. `static` добавляйте только тогда,
когда нужен один общий массив с сохранением содержимого между вызовами.

Если размер произвольный или данные должны пережить вызов, обычно памятью
управляют явно через `malloc` и `free` либо передают в функцию готовый буфер
и его вместимость. При динамическом выделении нужно проверять размер,
успех выделения и заранее договориться, кто освобождает память.
Это уже отдельная тема: время жизни такой памяти не привязано к стековому
кадру переменной-указателя.

## Проверьте себя

### 1. Два одинаковых имени

```c
int value = 1;
{
    int value = 2;
    ++value;
    printf("%d\n", value);
}
printf("%d\n", value);
```

Что выведется? Менялся ли внешний объект?

<details markdown="1">
<summary>Ответ</summary>

3, затем 1. Внутреннее объявление создало другой объект и скрыло внешнее имя.
Внешний объект всё это время существовал и не изменялся.

</details>

### 2. Локальное имя, долгая жизнь

```c
int Next(void) {
    static int value = 10;
    return ++value;
}
```

Что вернут два последовательных вызова? Можно ли обратиться к `value` из `main`?

<details markdown="1">
<summary>Ответ</summary>

11 и 12. Объект один на всё выполнение программы, но имя доступно только
внутри `Next`. Время хранения и область видимости отвечают на разные вопросы.

</details>

### 3. Какие массивы допустимы?

Все объявления находятся внутри функции:

```c
int n = 5;
const int size = 5;
enum { LIMIT = 5 };

int a[5];
int b[n];
static int c[n];
static int d[size];
static int e[LIMIT];
```

Какие объявления переносимы в C17, какое требует поддержки VLA,
а какие нельзя использовать в переносимом коде?

<details markdown="1">
<summary>Ответ</summary>

`a` и `e` допустимы: размер задан целочисленным константным выражением.
У `a` автоматическое время хранения, у `e` — статическое.
`b` — допустимый автоматический VLA в реализации, которая поддерживает VLA.
`c` и `d` недопустимы в переносимом C17: массив переменной длины не может
иметь статическое время хранения. `const int` не заменяет элемент `enum`.

</details>

## Что запомнить

- Стековый кадр помогает реализации хранить данные конкретного вызова.
- Область видимости определяет, где доступно имя; время хранения — когда живёт объект.
- Локальный `static` имеет локальное имя, но существует всё выполнение программы.
- Фиксированный размер и статическое время хранения — разные свойства массива.
- Автоматический VLA может получать размер при выполнении; статический VLA в C17 запрещён.

Формальные правила: [проект стандарта C11 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf),
§6.2.1 (области видимости), §6.2.4 (время хранения), §6.6 (константные выражения),
§6.7.6.2 (массивы). Рассмотренные правила действуют и в C17.
