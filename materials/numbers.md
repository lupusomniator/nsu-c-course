# Как числа хранятся в битах

## 1. Из битов получается число

У десятичного числа каждая позиция имеет свой вес: единицы, десятки, сотни.
У двоичного веса такие: 1, 2, 4, 8, 16 и далее степени двойки.

```text
Биты:       0   0   0   0   1   1   0   1
Вес:      128  64  32  16   8   4   2   1

00001101₂ = 8 + 4 + 1 = 13₁₀
```

В восьми битах есть 256 различных комбинаций. Если все они обозначают
неотрицательные целые, можно представить числа от 0 до 255.
Для `N` битов значения диапазона — **от 0 до 2^N − 1**.

В C17 двоичная запись `0b1101` не является стандартным синтаксисом
(но некоторые компиляторы принимают её как расширение). Можно использовать
десятичную или шестнадцатеричную запись:

```c
unsigned int first = 13;
unsigned int second = 0x0D;
printf("%u %u\n", first, second); // 13 13
```

Одна шестнадцатеричная цифра обозначает четыре бита. Поэтому `0xD` — это
`1101`, а `0xFF` — `11111111`. Такая запись удобна, когда интересуют
конкретные группы битов.

### Сколько битов в типе C?

`int` далеко не всегда занимает четыре байта. Это зависит от того, на какой архитектуре запускается программа и как она компилировалась. Настоящий размер типа можно узнать в самой программе:

```c
#include <limits.h>
#include <stdio.h>

// Внутри main:
printf("char bits: %d\n", CHAR_BIT);
printf("int bytes: %zu\n", sizeof(int));
printf("int range: %d .. %d\n", INT_MIN, INT_MAX);
printf("unsigned int max: %u\n", UINT_MAX);
```

`sizeof` измеряет размер в **байтах C**. Один такой байт содержит `CHAR_BIT`
битов; на обычных современных компьютерах это 8, но язык не требует ровно 8.
Всегда выполняется `sizeof(char) == 1`. У некоторых целых типов возможны
биты заполнения, поэтому размер объекта в битах не всегда равен числу
битов, участвующих в представлении значения.

Если нужен тип ровно из 32 битов, смотрят на `uint32_t` и `int32_t`
из `<stdint.h>`. Эти типы предоставляются только тогда, когда реализация
может обеспечить нужное представление без битов заполнения.
В трушном Си-коде для печати чисел используют макросы из `<inttypes.h>`:

```c
#include <stdint.h>
#include <inttypes.h>

uint32_t value = UINT32_C(4000000000);
printf("%" PRIu32 "\n", value); // 4000000000
```

Связано это с тем, что известные спецификаторы печати вроде `%d` или `%lu` работают по размеру типа (`%d%` - используется для 4-байтных значений, `%lu` - для 8-байтных).
А как уже было сказано, `int` - это не всегда 4 байта.

## 2. Беззнаковые целые: арифметика по кругу

У беззнакового типа нет отрицательных значений. Если результат операции
не помещается, он приводится по модулю числа представимых значений:

```c
unsigned int value = UINT_MAX;
value += 1u;
printf("%u\n", value); // 0

value = 0u;
value -= 1u;
printf("%u\n", value); // UINT_MAX, например 4294967295
```

Для восьми битов это легко увидеть на бумаге:

```text
  11111111  (255)
+ 00000001  (1)
----------
1 00000000  (256)
  └──────┘
Остаются младшие восемь битов: 0.
```

Здесь "возврат к нулю" — определённое поведение языка, а не случайность
конкретного процессора. Но результат всё равно может быть ошибкой алгоритма:
например, отрицательное математическое значение остатка превратится
в огромное положительное число.

Узкие целые типы сначала могут продвигаться до `int`. Например, для
`unsigned char` на обычной платформе сумма вычисляется как `int`, а затем
приводится при присваивании обратно. Поэтому в примере выше использован
именно `unsigned int`: не нужно путать тип хранения и тип вычисления.

## 3. Отрицательные числа: дополнительный код

Как разделить те же комбинации битов между положительными и отрицательными
значениями? На современных платформах обычно используется **дополнительный
код**, или two's complement.

Для восьми битов диапазон такого знакового типа — от −128 до 127.
Можно считать, что вес старшего бита равен −128, а остальные веса
положительны:

```text
Биты:       1   1   1   1   1   1   0   1
Вес:     -128  64  32  16   8   4   2   1

11111101₂ = -128 + 64 + 32 + 16 + 8 + 4 + 1 = -3
```

Другой способ получить представление −3: взять представление 3,
инвертировать все биты и прибавить единицу, оставив восемь битов:

```text
 3: 00000011
    11111100  <- инвертировали
-3: 11111101  <- прибавили 1
```

Старший бит указывает на отрицательное значение, но остальные биты
**не хранят просто модуль числа**. `10000011` в дополнительном коде — это
−125, а не −3.

Для `N` битов диапазон — **от −2^(N−1) до 2^(N−1) − 1**.
Отрицательных значений на одно больше: для 32-битного `int` это
−2147483648 ... 2147483647. Поэтому положительный аналог `INT_MIN`
в таком `int` не помещается.

Важная граница переносимости: **C17 допускает и другие представления
обычных знаковых целых**. Далее, когда обсуждаем конкретные знаковые биты,
предполагаем дополнительный код. Если реализация предоставляет `int32_t`,
для него C17 требует именно дополнительный код без заполнения.

### Дополнительный код не разрешает знаковое переполнение

```c
int value = INT_MAX;
value += 1; // Неопределённое поведение.
```

Даже если процессор при обычном сложении оставляет младшие биты, язык
не обещает здесь получить `INT_MIN`. Компилятор вправе оптимизировать код
исходя из того, что знакового переполнения в корректной программе нет.
См. [GNU: Integer Overflow](https://www.gnu.org/software/c-intro-and-ref/manual/html_node/Integer-Overflow.html).

Проверять переполнение нужно **до** операции. Например, для прибавления единицы:

```c
if (value < INT_MAX) {
    ++value;
} else {
    puts("Cannot increment");
}
```

Та же осторожность нужна с `-INT_MIN`, `abs(INT_MIN)` и `INT_MIN / -1`
на платформе с дополнительным кодом: положительный результат не помещается.

## 4. Побитовые операции и смешение типов

Операторы `&`, `|`, `^` и `~` работают с битами: И, ИЛИ, исключающее ИЛИ
и инверсия. Они отличаются от логических `&&`, `||` и `!`.

```c
unsigned int flags = 0u;
unsigned int mask = 1u << 3; // 00001000: бит с номером 3, считая от нуля.

flags |= mask;              // Установить бит.
printf("%d\n", (flags & mask) != 0u); // 1: проверить бит.
flags &= ~mask;             // Сбросить бит.
flags ^= mask;              // Переключить бит.
```

Для масок удобны беззнаковые типы. Сдвиг на отрицательное число позиций
или на число, не меньшее ширины продвинутого левого операнда, недопустим.
Левый сдвиг отрицательного знакового значения имеет неопределённое поведение;
правый сдвиг отрицательного в C17 зависит от реализации. Даже с положительным
знаковым значением левый сдвиг требует проверки представимости результата.

Ещё одна ловушка — сравнение знакового и беззнакового:

```c
int debt = -1;
unsigned int count = 1u;

// debt < count даст ложь.
```

При таком сочетании типов `debt` преобразуется в `unsigned int` и становится
`UINT_MAX`. Сравнение фактически проверяет `UINT_MAX < 1u`.
Это правило преобразования типов, а не изменение исходного `debt`.

Если отрицательный `debt` действительно должен считаться меньшим любого
`count`, проверку можно записать явно:

```c
int isLess = debt < 0 || (unsigned int)debt < count;
```

Приведение выполняется только после того, как отрицательные значения
обработаны отдельно. Приведение "лишь бы убрать предупреждение" может скрыть ошибку.

## 5. Число и порядок байтов — разные вещи

Возьмём 32-битное беззнаковое число `0x12345678`. Его старший байт — `0x12`,
младший — `0x78`. В памяти байты могут располагаться в разном порядке:

```text
Адреса растут слева направо.

little-endian: 78 56 34 12
big-endian:    12 34 56 78
```

Значение числа в обоих случаях одинаково. Порядок становится важен,
когда мы рассматриваем память как байты, читаем файл или передаём данные по сети.
Именно поэтому `pack` из [материала о структурах](struct.md) не задаёт
полный формат данных.

Посмотреть представление объекта можно через `unsigned char*`:

```c
void PrintBytes(const void* object, size_t size) {
    const unsigned char* bytes = object;
    for (size_t i = 0; i < size; ++i) {
        printf("%02X%s", (unsigned int)bytes[i],
               i + 1 == size ? "\n" : " ");
    }
}
```

Вызывать, например, так: `PrintBytes(&value, sizeof(value));`.
Доступ к байтам представления через символьный тип разрешён.
Рабочая программа для платформы с 8-битным байтом: [numberBits.c]({{ '/materials/examples/numberBits.c' | relative_url }}).

## 6. Дробь в двоичной системе

После двоичной точки веса идут в другую сторону: 1/2, 1/4, 1/8 и так далее.

```text
0.101₂ = 1/2 + 0/4 + 1/8 = 0.625₁₀
```

Поэтому некоторые десятичные дроби хранятся точно: например, 0.5, 0.25,
0.125. Но 0.1 в двоичной системе — бесконечная периодическая дробь:

```text
0.1₁₀ = 0.00011001100110011...₂
```

Это похоже на запись 1/3 в десятичной системе: сколько бы цифр мы ни выписали,
конечная запись не будет точной. Для двоичной дроби конечная запись возможна,
когда знаменатель несократимой дроби — степень двойки. Даже тогда для хранения
должно хватать разрядов и диапазона выбранного типа.

## 7. Зачем нужна плавающая точка

Если всегда отводить одно и то же число битов до и после точки, трудно
одновременно работать с очень большими и очень маленькими значениями.
Вместо этого число представляют в виде значащей части и степени основания:

```text
13.25₁₀ = 1101.01₂ = 1.10101₂ × 2³
```

Точка как будто перемещается, а степень сообщает, куда её нужно вернуть.
Отсюда название "плавающая точка".

На большинстве учебных платформ `float` соответствует IEEE 754 **binary32**,
а `double` — **binary64**. Дальше разбираем именно эти форматы.
C17 не требует их от любой реализации; размер `long double` и его точность
также зависят от платформы.

| Формат | Всего битов | Знак | Поле порядка | Поле дроби | Точность нормального числа |
| --- | --- | --- | --- | --- | --- |
| binary32 (`float`) | 32 | 1 | 8 | 23 | 24 двоичных разряда |
| binary64 (`double`) | 64 | 1 | 11 | 52 | 53 двоичных разряда |

У нормального ненулевого числа ведущая цифра всегда 1. Её можно не хранить,
а подразумевать. Поэтому при 23 сохранённых битах дроби получаем 24 разряда
значащей части. Её часто называют мантиссой.

Для нормального binary32 значение вычисляется так:

```text
(-1)^s × (1 + F / 2²³) × 2^(E − 127)
```

Здесь `s` — бит знака, `E` — беззнаковое значение поля порядка,
`F` — беззнаковое значение поля дроби. Число 127 — смещение порядка:
оно позволяет хранить отрицательные и положительные степени в беззнаковом поле.
Для binary64 используются 52 бита дроби и смещение 1023.

### Соберём 13.25 вручную

Число положительное, поэтому `s = 0`. Из записи `1.10101₂ × 2³` получаем
`E = 3 + 127 = 130`, то есть `10000010₂`. Ведущую единицу опускаем,
а дробную часть дополняем нулями:

```text
знак   порядок    дробь
0      10000010   10101000000000000000000

Полные 32 бита: 01000001010101000000000000000000
В hex:         0x41540000
```

Байты такого `float` будут `00 00 54 41`.
Это можно увидеть в `numberBits.c`.
Описание форматов: [Microsoft: IEEE Floating-Point Representation](https://learn.microsoft.com/en-us/cpp/build/ieee-floating-point-representation?view=msvc-170).

## 8. Ноль, очень маленькие числа, бесконечность и NaN

Крайние значения поля порядка зарезервированы. Для binary32:

| Поле порядка `E` | Поле дроби `F` | Значение |
| --- | --- | --- |
| 1 ... 254 | Любое | Нормальное число по формуле выше |
| 0 | 0 | `+0` или `-0`, в зависимости от знака |
| 0 | Не ноль | Субнормальное число: без подразумеваемой ведущей единицы |
| 255 | 0 | `+∞` или `−∞` |
| 255 | Не ноль | NaN: результат, не являющийся обычным числом |

Субнормальные числа заполняют промежуток между нулём и наименьшим нормальным
положительным числом. Для них формула — `(-1)^s × (F / 2²³) × 2^(-126)`.
Чем ближе к нулю, тем меньше значащих двоичных разрядов остаётся.

`+0.0` и `-0.0` сравниваются как равные, хотя имеют разные биты знака.
Проверить знак можно через `signbit` из `<math.h>`.
NaN не равен даже самому себе: для проверки используйте `isnan`,
а не `value == NAN`. Также доступны `isfinite` и `isinf`.

Не переносите свойства IEEE 754 на произвольную реализацию C17.
Например, обычный переносимый C-код не должен рассчитывать, что деление
на ноль обязательно создаст бесконечность. Для учебных проверок специальных
значений можно использовать `INFINITY` и `NAN` из `<math.h>` там,
где соответствующие значения поддерживаются.

## 9. Откуда берётся `0.30000000000000004`

```c
double left = 0.1;
double right = 0.2;
double sum = left + right;

printf("%.17g\n", sum);       // 0.30000000000000004
printf("%d\n", sum == 0.3);   // 0
```

Такой результат ожидается для binary64 с обычным округлением к ближайшему.
Сначала литералы 0.1 и 0.2 заменяются ближайшими доступными представлениями.
Затем складываются эти приближения, и результат снова округляется.
Число, полученное для литерала 0.3, оказывается соседним представимым значением.

Обычный `%f` печатает только шесть цифр после точки и может скрыть различие.
Формат `%.17g` показывает больше значащих цифр, а `%a` позволяет увидеть
значение в шестнадцатеричной форме с двоичным порядком:

```c
printf("%a\n", 0.1); // Обычно 0x1.999999999999ap-4
```

`p-4` означает умножение на `2^(-4)`. Число не изменилось от выбора формата
вывода — мы лишь попросили точнее его показать.

Литерал `0.1` имеет тип `double`, а `0.1f` — `float`.
Присваивание `double value = 0.1f;` расширит уже округлённое значение
`float`: потерянные разряды обратно не появятся.
При передаче в `printf` значение `float` автоматически продвигается до `double`.

## 10. Точность — это не количество цифр после точки

У binary32 есть 24 двоичных значащих разряда. Все целые от 0 до `2²⁴`
представимы точно, но дальше соседние значения идут уже с шагом 2:

```c
float value = 16777216.0f; // 2²⁴
float next = value + 1.0f;
printf("%.0f %.0f\n", value, next); // 16777216 16777216
```

Математическая сумма попала ровно между двумя представимыми числами.
При обычном режиме округления к ближайшему с выбором чётного на середине
получилось исходное значение.

Чем больше порядок, тем больше расстояние между соседними числами.
Для binary64 аналогичная граница точного представления всех подряд идущих
целых — `2⁵³`. Поэтому `double` не заменяет целый тип для произвольных
64-битных идентификаторов.

Параметры реализации находятся в `<float.h>`:

```c
printf("radix=%d float digits=%d double digits=%d\n",
       FLT_RADIX, FLT_MANT_DIG, DBL_MANT_DIG);
printf("epsilon=%.17g\n", DBL_EPSILON);
```

На обычной платформе первая строка даст `2`, `24`, `53`.
`DBL_EPSILON` — расстояние от 1 до следующего большего значения `double`,
а не универсальная погрешность любого вычисления.
`FLT_MIN` — наименьшее **положительное нормальное** значение `float`,
а не самое отрицательное. Для наименьшего положительного значения,
включая субнормальные, есть `FLT_TRUE_MIN`.

### Порядок вычислений влияет на результат

```c
double large = 1e16;
double firstStep = large + (-large);
double first = firstStep + 1.0;
double secondStep = -large + 1.0;
double second = large + secondStep;

printf("%.0f %.0f\n", first, second); // Обычно 1 0 для binary64.
```

В первом варианте большие числа сократились до прибавления единицы.
Во втором единица потерялась при округлении промежуточного результата.
Математическая ассоциативность сложения для вычислений с округлением не сохраняется.
Примеры рассчитаны на обычный режим компиляции без `-ffast-math` и аналогов,
разрешающих дополнительные преобразования выражений.

## 11. Как сравнивать и преобразовывать числа

`==` не запрещён для `double`: он точно проверяет равенство хранимых значений.
Но если нужно проверить близость результатов вычисления, задайте допустимую
ошибку в терминах задачи.

Например, если два измерения длины считаются одинаковыми при расхождении
не больше 0.001 метра:

```c
#include <math.h>

// Для конечных значений в диапазоне нашего измерительного прибора.
int isClose = fabs(measured - expected) <= 0.001;
```

Для величин разного масштаба часто сочетают абсолютный и относительный допуски:
`|a − b| <= max(absTol, relTol × max(|a|, |b|))`.
Абсолютный допуск помогает около нуля, относительный учитывает масштаб.
Оба выбираются по задаче; для NaN, бесконечностей и крайних величин нужны
отдельные правила. Подставлять везде `DBL_EPSILON` или `1e-9` без обоснования
не стоит.

Преобразование к целому отбрасывает дробную часть в направлении нуля:

```c
int whole = (int)-3.9;
printf("%d\n", whole); // -3
```

Это допустимо, только если получившаяся целая часть представима в целевом
типе. Преобразование огромного значения, бесконечности или NaN в `int`
не является способом получить безопасное "ближайшее" целое.

Ещё один важный момент: тип результата не меняет уже выполненную операцию.

```c
double first = 1 / 2;   // Сначала целочисленное деление: 0, затем 0.0.
double second = 1.0 / 2; // Деление с плавающей точкой: 0.5.
```

И приведение `(uint32_t)someFloat` преобразует **значение**, а не копирует
его биты. Для просмотра представления используйте доступ через
`unsigned char` или `memcpy`. Разыменование `(uint32_t*)&someFloat`
нарушает правила доступа через типы и не подходит для переносимого исследования.

## Проверьте себя

### 1. Одни биты, разные значения

Что означает `11111110` как беззнаковое восьмибитное число и как знаковое
в дополнительном коде? Можно ли из этого сделать вывод, что `INT_MAX + 1`
обязательно даст `INT_MIN`?

<details markdown="1">
<summary>Ответ</summary>

254 и −2. Нет: представление битов и правила операций — разные вопросы.
Переполнение знакового `int` имеет неопределённое поведение.

</details>

### 2. Соберите `float`

Представьте 5.5 в двоичной системе. Найдите знак, поле порядка и поле дроби
для binary32.

<details markdown="1">
<summary>Ответ</summary>

`5.5 = 101.1₂ = 1.011₂ × 2²`. Знак — 0, порядок — `2 + 127 = 129`,
то есть `10000001`. Дробь — `01100000000000000000000`.
Итоговая запись — `0x40B00000`; при little-endian байты идут `00 00 B0 40`.

</details>

### 3. Что теряется первым?

```c
double first = 1 / 2;
double second = 0.1f;
float third = 16777216.0f + 1.0f;
```

Почему ни одна из этих строк не исправляется простым присваиванием результата
в переменную типа `double`?

<details markdown="1">
<summary>Ответ</summary>

В первой строке уже выполнено целочисленное деление и потеряна дробная часть.
Во второй сначала округлён литерал типа `float`, затем его значение точно
расширено до binary64. В третьей сложение выполняется с точностью `float`
в обычной реализации binary32 и единица теряется при округлении.
Расширение готового результата не возвращает потерянную информацию:
менять типы нужно до операции, например `1.0 / 2` или `16777216.0 + 1.0`.

</details>

## Что запомнить

- Беззнаковая арифметика работает по модулю; знаковое переполнение недопустимо.
- Число битов, знаковость и порядок байтов отвечают на разные вопросы.
- Плавающая точка хранит конечное число значащих разрядов, а не любую дробь точно.
- Точность не восстанавливается расширением уже округлённого результата.
- Допуск при сравнении выбирают по задаче, а параметры типов проверяют по заголовкам.

§6.2.6 (представления), §6.3.1 (преобразования), §6.5.7 (сдвиги),
§5.2.4.2.2 (параметры вещественных типов). Здесь используем соответствующие правила C17.
