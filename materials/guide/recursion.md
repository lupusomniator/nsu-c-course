# Рекурсия

{% include course-context.html %}

Функция может вызывать другую функцию. Она также может вызвать саму себя —
это **рекурсия**. Она удобна, когда решение задачи выражается через решение
такой же задачи меньшего размера.

## Сумма через меньшую сумму

Сумма от 1 до 3 — это `3` плюс сумма от 1 до 2. Для нуля сумма равна нулю.

Вывод — `6`. В полном примере используется только `n == 3`.
Функция рассчитана на небольшие неотрицательные значения, для которых
сумма помещается в `int` и глубина вызовов допустима.

`n == 0` — **базовый случай**: ответ известен без нового вызова.
`SumTo(n - 1)` — рекурсивный шаг, приближающий аргумент к этому случаю.

## Вызовы не делят один параметр

```text
SumTo(3): n = 3, ждёт rest = SumTo(2)
  SumTo(2): n = 2, ждёт rest = SumTo(1)
    SumTo(1): n = 1, ждёт rest = SumTo(0)
      SumTo(0): возвращает 0
    SumTo(1): rest = 0, возвращает 1
  SumTo(2): rest = 1, возвращает 3
SumTo(3): rest = 3, возвращает 6
```

У каждого активного вызова собственные `n` и `rest`. Вычисление `n - 1`
передаёт меньшее число, но не меняет параметр ожидающего вызова.
Когда вложенный вызов заканчивается, продолжается именно ожидавшая функция.

## Две причины остановки

Для корректного завершения мало написать базовый случай. Нужно также,
чтобы каждый шаг двигался к нему. При отрицательном `n` выражение `n - 1`
будет удалять значение от нуля. Поэтому ограничения аргумента — часть
описания функции, а не необязательное замечание.

Отдельная проблема — ресурсы. Миллион вызовов может исчерпать стек,
даже если математически рекурсия должна закончиться.
Для простой суммы цикл требует меньше служебной памяти и обычно удобнее.

## Где рекурсия естественна

Вложенная структура часто разбирается рекурсивно. Например, у папки есть
файлы и вложенные папки: обработка каждой вложенной папки повторяет ту же идею.
Другой пример — дерево: узел содержит данные и ссылки на дочерние узлы.
Если дочернего узла нет, обработка этой ветви заканчивается.

Чтобы реализовать дерево, понадобятся уже знакомые структуры и указатели,
а для создаваемых при работе узлов — динамическая память. Рекурсия отвечает
за обход; сама по себе она не создаёт и не освобождает эти узлы.

## Как разбирать рекурсивную программу

Полезно разделять два движения: сначала вызовы углубляются, затем результаты
возвращаются. Для маленького аргумента можно записать рядом с каждым вызовом
его параметры и место, где он ждёт результат. Это та же таблица состояния,
что и у цикла, но с несколькими одновременно активными вызовами.

Отладчик показывает их как стек вызовов. Действие «шаг с заходом» переходит
в вызванную функцию, «шаг с обходом» выполняет вызов целиком и останавливается
на следующей строке вызывающей функции.
