# Символы и строки

{% include course-context.html %}

Текст в C обычно хранится в массиве элементов типа `char`.
Чтобы понять, где заканчивается текст, используется специальный нулевой элемент.

## Символ и строка

`'A'` в одинарных кавычках — символьная константа. В C такая обычная константа
имеет тип `int`; её код можно сохранить в `char`.
`"A"` в двойных кавычках — строковый литерал: массив с символом `A` и завершающим нулём.

```c
char word[] = "cat";
```

Компилятор определит размер массива по инициализатору:

```text
Индекс:      0     1     2      3
Элемент:   'c'   'a'   't'   '\0'
```

`'\0'` — значение ноль, отмечающее конец строки. Это не символ цифры `'0'`.
В `word` четыре элемента, хотя видимых символов три.
`'\n'` обозначает перевод строки, `'\t'` — табуляцию.

```c

```

Вывод:

```text
cat: 3
Cat
```

Цикл идёт до завершающего нуля. `%s` выводит строку, тоже останавливаясь на нуле.
Оба способа предполагают, что нулевой элемент действительно есть в доступной памяти.

`sizeof(word)` даёт размер массива вместе с завершающим нулём — `4`.
Функция `strlen(word)` из `<string.h>` считает длину до нуля — `3`.
Она возвращает `size_t` и не знает вместимость массива.

Литерал менять нельзя. `char word[] = "cat"` создаёт отдельный изменяемый массив,
поэтому `word[0] = 'C';` здесь разрешено.

## Чтение строки с пробелами

`scanf("%s", ...)` останавливается на пробельном символе. Для целой строки
используют `fgets` из `<stdio.h>`:

```c
char line[80];
if (fgets(line, sizeof(line), stdin) == NULL) {
    printf("No line\n");
    return 1;
}
printf("%s", line);
```

Здесь **буфер** — массив, выделенный для ввода. `stdin` обозначает стандартный
входной поток. Для массива из 80 элементов `fgets` читает не более 79 символов
и при успехе добавляет `\0`. Если встретился перевод строки и для него есть
место, он сохраняется в массиве.

Возвращаемое значение `NULL` обозначает отсутствие полученной строки из-за
конца ввода или ошибки. Это нулевой указатель; подробное объяснение будет
в следующей главе. Сейчас он используется только для проверки результата.

Если строка длиннее буфера, остаток остаётся во входе. Такой результат
нельзя считать полной строкой. Программа должна выбрать политику: дочитать
остаток, увеличить буфер или сообщить, что строка слишком длинная.

## Откуда берётся «пустой ввод»

После `scanf("%d", &value)` перевод строки обычно остаётся во входе.
Следующий `fgets` может прочитать именно его. Поэтому для последовательного
построчного ввода проще читать все строки через `fgets`, а затем разбирать их.

Для преобразования строки в целое есть `strtol` из `<stdlib.h>`. Он позволяет
обнаруживать выход за диапазон и узнать, где закончилась числовая часть.
При строгом разборе проверяют: были ли цифры, не возник ли выход за диапазон,
что осталось после числа и помещается ли оно в нужный тип. Для работы с этими
результатами понадобятся указатели. Простая проверка `scanf` из [главы о вводе](input.md) имеет более узкую область применения.

## Сравнение и кодировка

Для сравнения содержимого строк есть `strcmp` из `<string.h>`:
результат `0` означает равенство, отрицательный — что первая строка меньше,
положительный — что больше. Не нужно ожидать ровно `-1` или `1`.
`==` не сравнивает содержимое двух массивов строк.

Примеры используют латинские буквы. В UTF-8 русская буква занимает несколько
байтов, поэтому индекс массива и `strlen` считают байты, а не видимые буквы.
Разворот массива по одному байту может испортить такой текст.

## Изменение строки на месте: два индекса

Рассмотрим более содержательный пример: удалим из строки все обычные пробелы,
сохранив порядок остальных символов. Дополнительный массив не нужен:
запись будет отставать от чтения.

```c
{% include_relative examples/compactString.c %}
```

Вывод — `[Cisfun]`. Квадратные скобки в выводе помогают увидеть начало
и конец результата, но в самой строке их нет.

`read` — индекс просматриваемого символа. `write` — место для следующего
сохраняемого символа. На пробеле увеличивается только `read`; на остальных
символах копируется значение и увеличиваются оба индекса.

Для короткого входа `" a b"`:

| `read` | Прочитанный символ | `write` до шага | Действие |
| --- | --- | --- | --- |
| 0 | Пробел | 0 | Пропустить |
| 1 | `a` | 0 | Записать `a` в `line[0]`, увеличить `write` до 1 |
| 2 | Пробел | 1 | Пропустить |
| 3 | `b` | 1 | Записать `b` в `line[1]`, увеличить `write` до 2 |
| 4 | `\0` | 2 | Закончить цикл, записать `\0` в `line[2]` |

В каждый момент `write <= read`: сохраняем символов не больше,
чем уже прочитали. Значит, запись никогда не испортит ещё не просмотренный
символ. После цикла обязательно нужен новый нулевой элемент: иначе `%s`
продолжит читать старый хвост массива.

Для пустой строки цикл не начнётся, и ноль снова запишется на позицию 0.
Для строки из одних пробелов `write` останется нулём, результат тоже будет
пустым. Без пробелов каждый символ присваивается на прежнее место.
В примере удаляется именно `' '`, а не любая табуляция или перевод строки.

Строки показали, что функций часто интересует место, где находятся данные.
Следующая глава подробно разберёт эти адреса и расширит копирование
элементов до универсальной работы с байтами объектов.
