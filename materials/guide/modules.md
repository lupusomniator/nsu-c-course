# Программа из нескольких файлов

{% include course-context.html %}

Когда программа растёт, функции удобно распределять по файлам.
Пользователю функции важно знать, как её вызвать; её внутреннее устройство
можно хранить отдельно.

## Три файла одного примера

Будем вычислять большее из двух целых чисел. **Интерфейс** функции — её имя,
типы параметров и результата, а также смысл действия.
**Реализация** — код, который выполняет это действие.

Заголовок `maximum.h` содержит объявление:

```c
{% include_relative examples/modules/maximum.h %}
```

Файл `maximum.c` содержит определение с телом:

```c
{% include_relative examples/modules/maximum.c %}
```

Файл `program.c` использует интерфейс:

```c
{% include_relative examples/modules/program.c %}
```

Вывод программы — `8`. Исходники доступны в
[каталоге примеров](../examples.md#многофайловый-пример).

## Что делает include

До компиляции **препроцессор** обрабатывает директивы, начинающиеся с `#`.
`#include "maximum.h"` подставляет содержимое нашего заголовка в исходный файл.
Кавычки используются для заголовка проекта; `<stdio.h>` — форма подключения
стандартного заголовка.

В `maximum.h` строки `#ifndef`, `#define` и `#endif` образуют защиту
от повторного включения. `#ifndef` читается как «если это имя ещё не определено».
При первом включении задаётся имя `COURSE_MAXIMUM_H` и читается объявление.
При повторном включении в тот же обрабатываемый файл блок пропускается.
Подробно эти директивы разберём в главе о препроцессоре.

## Компиляция и компоновка

Каждый `.c` с подключёнными заголовками образует **единицу трансляции**.
Компилятор обрабатывает её отдельно и создаёт объектный файл.
**Компоновщик** соединяет объектные файлы и находит реализации вызываемых функций.

```text
program.c + maximum.h → program.o ──┐
                                   ├→ готовая программа
maximum.c + maximum.h → maximum.o ──┘
```

На Windows объектные файлы обычно имеют расширение `.obj`.
Следующие команды выполняют оба этапа сразу.

Из папки с тремя файлами, macOS/Linux:

```sh
cc -std=c17 -Wall -Wextra -Wpedantic program.c maximum.c -o program && ./program
```

Windows, Developer PowerShell:

```powershell
cl /nologo /TC /std:c17 /W4 /utf-8 program.c maximum.c /Fe:program.exe
if ($LASTEXITCODE -eq 0) { .\program.exe }
```

Заголовок не нужно передавать как отдельный исходник: он уже подключается
из `.c`. Файл реализации `.c` тоже не нужно подключать через `#include`.

## Две разные ошибки

Если компилятор не видел объявления `Maximum`, он не знает интерфейс функции.
Если объявление видел, но при сборке забыли `maximum.c`, ошибка возникает
при компоновке: `undefined reference` или `unresolved external symbol`.

Если обычное определение функции поместить в заголовок, который подключают
два `.c`, могут появиться два определения одной функции. Защита заголовка
не помогает: она действует отдельно внутри каждой единицы трансляции.

## Видимость между файлами

**Связывание** определяет, могут ли объявления имени обозначать одну сущность
в разных местах программы. У обычной функции вроде `Maximum` оно внешнее:
другой `.c` может обратиться к этому определению.

`static` перед функцией на уровне файла делает её внутренней для этой
единицы трансляции. Так можно скрыть вспомогательные функции модуля.
Это другое применение `static`, чем у локального счётчика в [главе о времени жизни](lifetime.md).

Для общей переменной заголовок может содержать `extern int counter;` —
объявление без определения. Ровно один `.c` содержит `int counter = 0;`.
Обычно удобнее скрыть состояние в модуле и предоставить функции доступа:
тогда меньше мест могут случайно изменить данные.

## Как сюда относится CMake

CMake хранит описание сборки: из каких файлов состоит программа,
какие параметры нужны компилятору. Он организует вызовы инструментов,
но сам не заменяет компилятор. В небольшом примере достаточно одной команды;
для лабораторных есть [отдельная инструкция](../../how_to_cmake.md).

Мы умеем разделять программу на части. Далее рассмотрим данные,
для которых нужный размер памяти становится известен только при выполнении.
