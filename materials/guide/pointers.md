# Адреса и указатели

{% include course-context.html %}

Функция получает копии значений аргументов. Однако `scanf` изменяет переменную
вызывающего кода. Это возможно, потому что ей передаётся адрес этой переменной.

## Объект, адрес, указатель

**Объект** в языке C — область хранения данных. Обычная переменная обозначает
такой объект. **Адрес** позволяет обратиться к нему. **Указатель** — значение,
которое может указывать на объект; переменная указательного типа хранит это значение.

```c
int score = 10;
int* pointer = &score;
*pointer = 15;
```

`&score` получает адрес `score`. В объявлении `int*` означает «указатель на int».
В выражении `*pointer` звёздочка означает **разыменование** — обращение к объекту,
на который указывает указатель.

```text
pointer ───────→ score
                было 10
                стало 15
```

Запись через `*pointer` меняет `score`. Сам указатель продолжает указывать
на то же место. `pointer` и `*pointer` — разные вещи: адрес и объект по адресу.

`left` другой адрес, указатель вызывающего кода от этого не изменится.

## Когда разыменование допустимо

Указатель должен указывать на существующий объект подходящего типа,
доступный для нужной операции. Неинициализированный, нулевой или уже
недействительный указатель разыменовывать нельзя.

```c
int* selected = NULL;
```

`NULL` — обозначение нулевого указателя; оно доступно через `<stddef.h>`
и некоторые другие стандартные заголовки, в том числе `<stdio.h>`.
Так можно выразить «объект не выбран». Проверка `selected != NULL`
исключает только нулевой случай: она не доказывает, что любой другой адрес корректен.

`const int* pointer` разрешает читать `*pointer`, но запрещает изменять его
через этот указатель. Сам адрес можно заменить. `int* const pointer`
означает другую вещь: постоянный указатель, через который можно менять `int`.
`const` не превращает чужую изменяемую переменную в неизменяемую для всей программы.

## Массив как аргумент функции

В большинстве выражений имя массива преобразуется в указатель на его первый
элемент. Поэтому функцию суммы можно записать так:

```c
int Sum(const int* values, size_t count) {
    int result = 0;
    for (size_t i = 0; i < count; ++i) {
        result += values[i];
    }
    return result;
}
```

Здесь предполагается, что доступны `count` элементов и сумма помещается в `int`.
Вызов для `int values[3] = {2, 4, 6};` — `Sum(values, 3)`.
Функция получает адрес, а не копию всего массива. Длину нужно передать отдельно.

В параметрах `const int values[]` означает тот же указатель.
Поэтому `sizeof(values)` внутри такой функции даст размер указателя,
а не исходного массива. Массив и указатель связаны правилами языка,
но не являются одним и тем же типом объекта.

## Арифметика указателей

Если `pointer` указывает на элемент массива, `pointer + 1` указывает
на следующий элемент, независимо от размера элемента в байтах.
`values[i]` соответствует `*(values + i)`.

Такие перемещения допустимы внутри одного массива, включая позицию сразу
после последнего элемента. Указатель на эту последнюю позицию можно использовать
как границу, но разыменовывать его нельзя.

Строка передаётся похожим образом: `const char*` часто означает адрес
первого символа строки, которую функция только читает. В этом случае
конец определяется по `\0`, а не по отдельно переданной длине.

## Почему размер не путешествует вместе с адресом

Вызов `Sum(values, 3)` передаёт две независимые вещи: адрес первого элемента
и число элементов. Если передать `30`, функция не сможет узнать, что в исходном
массиве их всего три. Тип `const int*` говорит, **как обращаться к одному элементу**,
но не задаёт длину всей области.

Это важно и при работе с указателем на массив:

```c
{% include_relative examples/pointerRows.c %}
```

Вывод — `4 6`. `table` состоит из двух элементов, каждый из которых —
массив трёх `int`. При преобразовании имени `table` получается указатель
на **строку**, поэтому тип `row` — `int (*)[3]`.

В объявлении `int (*row)[3]` скобки связывают звёздочку с именем:
`row` — указатель на массив. Без них `int* row[3]` означало бы массив
из трёх указателей на `int`. Это разные устройства данных.

`++row` переходит через одну целую строку — три `int`, а не один.
`(*row)[0]` сначала выбирает строку по указателю, затем её первый элемент.
Тип `int**` здесь не подходит: он предполагал бы, что в памяти лежат
указатели на строки. В `table` подряд лежат сами числа.

## От обмена двух int к обмену двух объектов

Функция `Swap` выше знает тип `int`. Для `double` можно написать почти такую же,
для массива — ещё одну. Но последовательность действий везде одинаковая:
сохранить часть первого объекта, перенести соответствующую часть второго,
затем вернуть сохранённое во второй.

Чтобы выразить эту общую операцию, нужно отделить **значение** от его
**представления в памяти**. Объект занимает `sizeof` байтов. Мы можем
перенести их, не вычисляя новое значение каждого поля или элемента.
Здесь байт — единица `sizeof`, и `sizeof(unsigned char) == 1`.
Количество битов в таком байте не требуется для самого обмена.

### Что даёт void*

Параметр `void*` принимает адрес объекта без указания конкретного типа.
В C указатель на объект можно преобразовать в `void*` и обратно
к исходному типу, сохранив значение указателя. Это не меняет сам объект:
`int` по переданному адресу остаётся `int`.

Однако разыменовать `void*` для получения значения нельзя: не задан тип,
который нужно прочитать. Выражение `a + 1` для `void*` тоже не является
переносимым C — неизвестно, на сколько байтов двигаться.

Для доступа к представлению любого объекта язык специально разрешает
символьный тип. Выберем `unsigned char*`: он обращается к одному байту
за раз, а все его битовые комбинации допустимы. Присваивание
`unsigned char* left = a;` меняет способ доступа, не выделяя и не копируя память.

```c

```

Вывод:

```text

doubles: 2.50 1.25
arrays: 4 5 6 | 1 2 3
```

У `count` единица измерения — **байт**, не элемент. Для целого числа передаём
`sizeof(first)`, для целого массива — `sizeof(left)`. В вызове с массивами
`&left` и `&right` обозначают адреса целых массивов; функция обменяет
всё их представление. `sizeof` указателя вместо размера объекта привёл бы
к переносу другого количества байтов.

### Что происходит в одной итерации

Представим, что обмениваются три байта. Буквы обозначают их исходное содержимое,
а не конкретную кодировку числа:

```text
До начала:        left = [A0 A1 A2]    right = [B0 B1 B2]
После i = 0:      left = [B0 A1 A2]    right = [A0 B1 B2]
После i = 1:      left = [B0 B1 A2]    right = [A0 A1 B2]
После i = 2:      left = [B0 B1 B2]    right = [A0 A1 A2]
```

В начале итерации `i` первые `i` байтов уже обменены, остальные ещё исходные.
`temporary` сохраняет `Aᵢ`, затем `left[i]` получает `Bᵢ`, а `right[i]`
получает сохранённый `Aᵢ`. На следующем шаге свойство сохраняется.
После `count` шагов обменены все байты. Временного массива размером с объект
не понадобилось: достаточно одной переменной `unsigned char`.

### Точный договор о применении

Функция не знает размеров объектов и не умеет проверять произвольные адреса.
Поэтому вызывающий код отвечает за следующие условия:

- Обе области существуют, доступны для записи и содержат хотя бы `count` байтов.
- Области либо совпадают полностью, либо не пересекаются. Совпадающие адреса
  обрабатываются ранним возвратом. Частичное перекрытие не поддерживается.
- При `count == 0` переносить нечего: допустим и вызов `swap(NULL, NULL, 0)`.
- Для обмена типизированных значений нужно переносить полные представления
  объектов одного типа, как в примерах. Равенство размеров двух разных типов
  не означает совместимость их представлений.

Почему требуется отсутствие частичного перекрытия? Пусть массив содержит
`[1 2 3]`, а области — первые и последние два байта. Первый обмен даст
`[2 1 3]`; второй использует уже изменённую середину и даст `[2 3 1]`.
Это не независимый обмен двух исходных блоков. Даже требования к общему
байту могут конфликтовать: после одного обмена он должен стать `3`,
после другого — `1`. Поэтому такие аргументы исключены договором.

Нельзя заменить `unsigned char*` на `int*` и переносить «более крупными кусками»
без дополнительных условий. Адрес может не подходить по выравниванию,
размер может не делиться на `sizeof(int)`, а доступ к чужому объекту
через несовместимый тип нарушает правила языка.

## Указатель на указатель: изменение самого адреса

`swap` меняет данные по адресам. Иногда нужно заменить значение указателя
у вызывающего кода. Тогда передают адрес **самой переменной-указателя**:

```c
{% include_relative examples/selectPointer.c %}
```

Вывод — `selected=9 first=4 second=9`.
`selected` хранит адрес `first`. Параметр `output` получает `&selected`:
это указатель на объект типа `int*`, поэтому его тип — `int**`.
Строка `*output = right` записывает новый адрес в `selected`.

```text
До вызова:       selected → first
Внутри функции: output   → selected
После вызова:   selected → second
```

Если бы параметр был `int* output`, присваивание ему меняло бы только
локальную копию адреса. Дополнительная звёздочка появилась потому,
что изменяемый объект теперь сам является указателем.

Адрес позволяет найти объект, но не удерживает его в памяти. Следующая
глава разберёт, когда объект перестаёт существовать и почему сохранённый
адрес после этого уже не помогает.
