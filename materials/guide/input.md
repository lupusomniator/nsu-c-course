# Ввод данных

{% include course-context.html %}

До сих пор данные были записаны в исходном коде. Чтобы выполнить программу
с другими числами, приходилось менять файл и собирать его заново.
**Ввод** позволяет передать данные уже работающей программе.

## Прочитать число

```c
{% include_relative examples/readNumber.c %}
```

При вводе `12` программа печатает `Next: 13`. При вводе `cat` — `Expected an integer`
и завершается с кодом `1`. В нашей программе ненулевой код означает ошибку.

`scanf` читает текст из **стандартного ввода**. При обычном запуске в терминале
это ввод с клавиатуры. После набора числа нужно нажать Enter.
До этого программа может ждать — это не обязательно зависание.

В `scanf("%d", &value)` есть две отдельные инструкции для функции:

- `%d` просит прочитать запись целого числа для переменной типа `int`;
- `&value` сообщает, **куда записать** прочитанное значение.

Оператор `&` перед именем получает **адрес** переменной. Можно представлять
адрес как обозначение места, где хранится объект. Если передать просто `value`,
получится само число, а не место для записи. Подробнее адреса разберём
в главе об указателях; здесь у `&` ровно эта роль.

## Почему проверяется результат

Функция `scanf` возвращает количество успешно записанных значений.
В нашем примере ожидается одно, поэтому `!= 1` означает неудачу.
Ввод букв вместо числа может дать `0`. Если данные закончились до первого
преобразования, возможен специальный результат `EOF` — отрицательная константа.
Обе ситуации попадают в одну ветвь ошибки.

После неудачи программа не должна выполнять вычисления с непрочитанными данными.
Ранний `return 1;` заканчивает функцию, поэтому нижние строки уже не выполняются.
Ни `return 0`, ни `return 1` сами по себе не выводят сообщение.

## Пробелы, несколько чисел и дробные значения

Фрагмент для чтения двух целых:

```c
int width = 0;
int height = 0;
if (scanf("%d %d", &width, &height) != 2) {
    printf("Expected two integers\n");
    return 1;
}
```

Числа могут быть разделены пробелом или переводом строки. При `%d` начальные
пробельные символы пропускаются. Ввод `12 cats` запишет только первое число,
а функция вернёт `1`.

Для `double` при чтении нужен `%lf`, для `float` — `%f`.
При выводе `printf` использует `%f` для обоих: аргумент `float` автоматически
преобразуется в `double`. Форматы ввода и вывода нельзя механически копировать
друг в друга.

## Где заканчивается применимость простого примера

Здесь мы предполагаем, что введённые числа помещаются в `int`.
Проверка результата `scanf` не делает ввод произвольного огромного числа
безопасным: если преобразованное значение не представимо в целевом типе,
это не надёжный способ обнаружить ошибку.

Кроме того, `12abc` может успешно прочитаться как число `12`, оставив `abc`
во входе. `scanf` читает подходящее начало, а не проверяет всю строку.
Для строгой проверки текст сначала читают целиком и затем преобразуют
с контролем диапазона. К этому вернёмся в главе о строках.

В примере диапазон дополнительно ограничен числами от `0` до `100`.
Поэтому вычисление `value + 1` безопасно для `int`, а значение вне этого
диапазона получает понятное сообщение.

## Ввод из файла

Терминал может направить содержимое текстового файла в стандартный ввод.
Если файл `input.txt` содержит `12`, на macOS/Linux запуск выглядит так:

```sh
./readNumber < input.txt
```

В PowerShell для этого небольшого текстового примера:

```powershell
Get-Content input.txt | .\readNumber.exe
```

`<` и `|` здесь принадлежат командной оболочке. Программа C по-прежнему
вызывает тот же `scanf` и не знает имени файла. Автоматические проверки
пользуются похожим принципом: передают ввод и сравнивают полученный вывод.

Теперь можно обрабатывать разные данные без новой сборки. Для длинной
последовательности одинаковых действий понадобится цикл.
