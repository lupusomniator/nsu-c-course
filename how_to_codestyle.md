# Стиль кода лабораторных на C

Код должен быть понятен человеку, который впервые открыл вашу работу: где читаются данные, как устроен алгоритм и кто освобождает память. Для этого в лабораторных используем общие правила оформления и организации кода.

За основу взяты codestyle из Яндекса: разделение на модули, имена функций вроде `HeapSort`, типы `TNode`, отступы и оформление блоков.

Правила ниже обязательны, если пункт явно не назван рекомендацией. Число строк в функции и длина строки — ориентиры для читаемости, а не формальные ограничения.

## 1. Коротко о главном

| Что оформляем | Как пишем | Пример |
| --- | --- | --- |
| Отступ | 4 пробела, без табуляции | Каждый вложенный блок сдвигается на 4 пробела. |
| Функция | `UpperCamelCase` — каждое слово с большой буквы | `ReadArray`, `FindMinPath`, `FreeTree` |
| Переменная, параметр, поле структуры | `lowerCamelCase` — первое слово с маленькой буквы | `vertexCount`, `inputFile`, `node->left` |
| Тип структуры | `T` + `UpperCamelCase` | `TNode`, `TQueue`, `TTreeNode` |
| Тип перечисления | `E` + `UpperCamelCase` | `EReadStatus` |
| Именованная константа, элемент перечисления, макрос | `UPPER_SNAKE_CASE` — большие буквы и подчёркивания | `MAX_VERTEX_COUNT`, `READ_OK` |
| Файл модуля | `lowerCamelCase`, одинаковая основа у `.c` и `.h` | `minPath.c`, `minPath.h` |
| Указатель в объявлении | `*` рядом с типом | `int* values`, `const TNode* node` |
| Фигурные скобки | Открывающая на строке условия или функции | `if (isReady) {` |

`main` сохраняет стандартное имя. Имена стандартной библиотеки (`malloc`, `size_t`, `FILE`) также не меняем. Названия папок лабораторных остаются такими, как в шаблоне: `lab0`, `lab1-0` и т. д.

## 2. Имена должны объяснять назначение

Пишите имена по-английски, без транслита. Называйте переменную по тому, **что она хранит**, а функцию — по тому, **что она делает**:

```c
int vertexCount;
int currentIndex;
bool isVisited;
FILE* inputFile;

void FreeTree(TNode* root);
```

`a`, `b`, `tmp`, `data2` и `DoWork` заставляют читателя угадывать смысл. Лучше `distances`, `sourceVertex`, `temporaryValue` и `ReadGraph`.

Короткие имена уместны в небольшом понятном контексте: `i` и `j` как индексы цикла, `x` и `y` как координаты. Не нужно переименовывать каждый `i` в длинную фразу. Избегайте неочевидных сокращений вроде `curVrtxCnt`, когда можно написать `vertexCount`.

Поля структур тоже начинаются с маленькой буквы:

```c
typedef struct TNode {
    int value;
    struct TNode* left;
    struct TNode* right;
} TNode;

typedef enum EReadStatus {
    READ_OK,
    READ_INVALID_INPUT,
    READ_NO_MEMORY
} EReadStatus;
```

Изменяемая переменная не становится константой из-за того, что объявлена вне функции. Если модулю действительно нужно такое состояние, имя остаётся `lowerCamelCase`, а объявление делается `static` внутри `.c`. Обычно данные лучше передавать через параметры или структуру.

## 3. Пробелы, скобки и переносы

### Отступы и блоки

Используйте 4 пробела на уровень вложенности. Скобки обязательны у `if`, `else`, `for`, `while` и `do`, даже когда внутри одна строка:

```c
if (value < minValue) {
    minValue = value;
} else {
    ++greaterCount;
}

for (size_t i = 0; i < count; ++i) {
    values[i] = 0;
}
```

Открывающую скобку функции тоже ставьте на строке объявления, закрывающую — на отдельной строке. `else` пишите как `} else {`. Не помещайте всё тело функции или условного блока в одну строку.

### Пробелы

- После `if`, `for`, `while`, `switch` ставьте пробел перед `(`: `if (isReady)`.
- Между именем функции и `(` пробела нет: `FindMax(values, count, &result)`.
- После запятой и между частями `for` ставьте пробел.
- Вокруг бинарных операторов ставьте пробелы: `a + b`, `count >= 0`, `left && right`.
- Внутри `()`, `[]`, вокруг `.` и `->` дополнительных пробелов нет.
- Унарный оператор пишется рядом с операндом: `!isReady`, `&value`, `*result`, `++i`.

```c
int middle = left + (right - left) / 2;
int nextValue = values[index + 1];
node->value = nextValue;
```

### Объявления

Одна переменная — одно объявление. Это особенно важно для указателей:

```c
int* first;
int* second;
```

В записи `int* first, second;` указателем является только `first`. Раздельные объявления убирают эту ловушку.

Объявляйте переменную близко к первому использованию и сразу задавайте значение, когда оно известно. Не собирайте все переменные функции в длинный список в её начале.

### Длинные строки и пустые строки

Рекомендуемый ориентир — до **100 символов** в строке. Если выражение перестало помещаться удобно, перенесите его по смыслу:

```c
if (row < 0 || row >= rowCount ||
    column < 0 || column >= columnCount) {
    return false;
}
```

Разделяйте пустой строкой этапы работы: чтение, проверку, вычисление, вывод. Между функциями оставляйте одну пустую строку. Удаляйте пробелы в конце строк; в конце файла должна быть завершающая новая строка.

## 4. Простые выражения и понятные условия

Одна строка должна выполнять одно понятное действие. Не прячьте изменение переменной внутри вычисления, если это затрудняет чтение:

```c
// Сначала сдвигаем индекс, затем учитываем новое значение.
++index;
sum += values[index];
```

Отдельно написанные `i++` и `++i` допустимы. Главное — чтобы изменение индекса не терялось внутри другого действия.

Для обмена значений используйте временную переменную:

```c
static void Swap(int* first, int* second) {
    int temporaryValue = *first;
    *first = *second;
    *second = temporaryValue;
}
```

Обмен через сложение или XOR хуже читается, а вариант со сложением может вызвать переполнение.

Для логических значений используйте `bool`, `true`, `false` из `<stdbool.h>`, когда требуется именно флаг. Не используйте `char` только ради хранения признака «да/нет». Для указателя явно показывайте проверку: `node == NULL` или `node != NULL`.

Ранний `return` при ошибке допустим и часто уменьшает вложенность. После него обычно не нужен `else`:

```c
if (count == 0) {
    return false;
}

// Дальше работаем с непустым массивом.
```

Не используйте тернарный оператор для сложных вычислений с побочными эффектами и не вкладывайте несколько таких операторов друг в друга. Простое выражение вроде `left < right ? left : right` допустимо.

## 5. Константы вместо необъяснённых чисел

Если число задаёт ограничение задачи, размер буфера или специальное значение, дайте ему имя:

```c
#define MAX_VERTEX_COUNT 5000

typedef enum ECellState {
    CELL_WALL = -1,
    CELL_EMPTY = 0,
    CELL_VISITED = 1
} ECellState;
```

Числа `0`, `1`, `2` не нужно механически заменять константами, если их смысл очевиден, например в индексе ребёнка кучи `2 * index + 1`.

Для целочисленных констант времени компиляции используйте `enum` или `#define`. Для обычных значений подходит `const`. В C локальный `const int` не делает размер массива константой времени компиляции — учитывайте это, когда объявляете массив.

Различайте два случая: `const double EPSILON` — именованная постоянная величина, а `const TNode* node` — параметр `node`, через который нельзя изменять узел. Имя такого параметра остаётся `lowerCamelCase`.

Не заменяйте обычные функции макросами ради сокращения записи. Например, обмен значений оформите функцией `Swap`.

## 6. Функции и модули

### Разделяйте обязанности

`main` организует работу программы: получить данные, проверить их, вызвать алгоритм, вывести результат и освободить ресурсы. Алгоритм и операции над структурами данных выносите в отдельные функции и модули.

В `main.c` оставляйте `main` и небольшие функции чтения и первичной проверки входа. Например, сортировка, балансировка дерева и поиск пути должны находиться в своих модулях. Освобождение внутренней памяти дерева тоже относится к модулю дерева.

Рекомендуемая структура:

```text
labX/
├── CMakeLists.txt
└── src/
    ├── main.c
    └── lib/
        ├── array.c
        └── array.h
```

`src/lib` — рекомендуемая папка для модулей; сами имена файлов выбирайте по задаче: `queue`, `tree`, `minPath`. Не создавайте отдельную папку для каждой функции. Один модуль объединяет связанную работу, например операции с очередью.

По возможности отделяйте вычисления от ввода и вывода: функция поиска максимума возвращает результат, а вызывающий код решает, как его напечатать. Функции, чья задача прямо состоит во вводе или выводе, например `ReadGraph` или `PrintTree`, могут работать с потоками.

### Делайте функции обозримыми

Одна функция отвечает за одну задачу. Рекомендуемый ориентир — функция, которую удобно прочитать целиком на экране, часто это **20–40 строк**. Длинный алгоритм не нужно дробить механически: выделяйте осмысленные операции, а не куски с именами `Part1` и `Part2`.

Если внутри несколько уровней `if` и циклов, подумайте, нельзя ли проверить ошибку раньше или вынести отдельное действие в функцию.

Функция без параметров объявляется с `void`:

```c
int main(void);
```

В используемом на курсе C99 запись `Function()` в объявлении не означает то же самое, что `Function(void)`.

### Что помещать в `.h` и `.c`

В заголовке `.h` находятся типы, константы и объявления функций, которыми пользуются другие файлы. В `.c` — реализации.

- Защитите заголовок от повторного включения: в курсе используем `#pragma once`; обычный include guard через `#ifndef` / `#define` / `#endif` также допустим.
- Заголовок сам подключает стандартные заголовки, нужные для его объявлений. Например, для `size_t` нужен `<stddef.h>`, для `FILE` — `<stdio.h>`, для `bool` — `<stdbool.h>`.
- Внутренние функции, нужные только своему `.c`, объявляйте `static` и не добавляйте в `.h`.
- Не подключайте `.c` через `#include`. Все исходники собираются через CMake.
- Не определяйте изменяемые глобальные переменные в заголовках.

В исходнике модуля сначала подключайте его собственный заголовок, затем необходимые стандартные и другие проектные заголовки. Разделяйте группы пустой строкой. Это помогает заметить, если `.h` случайно зависит от чужих подключений.

```c
#include "array.h"

#include <stdlib.h>
```

В `main.c` сначала подключайте стандартные заголовки, затем заголовки своих модулей. Убирайте неиспользуемые `#include`.

## 7. Указатели, память и обработка ошибок

Эти правила помогают увидеть, как программа ведёт себя при ошибке, ещё до запуска тестов.

- Если функция только читает объект через указатель, используйте `const`: `const int* values`.
- При выделении памяти пишите размер через объект: `malloc(count * sizeof(*values))`. В C результат `malloc` приводить к типу указателя не нужно; подключите `<stdlib.h>`.
- До выделения массива проверьте, что количество элементов допустимо по условию и произведение на размер элемента помещается в `size_t`.
- Проверяйте результат `malloc` и `fopen` до первого обращения к памяти или файлу.
- Для `scanf` / `fscanf` проверяйте **число успешно прочитанных значений**: например, `scanf("%d %d", &a, &b) != 2`. Проверки только на `EOF` недостаточно: ввод может содержать неподходящие символы.
- Для каждого выделенного ресурса должно быть понятно, кто его освобождает. Освобождайте память и закрывайте файлы также на путях с ошибками.

Например, создание узла типа `TNode` из раздела 2:

```c
TNode* CreateNode(int value) {
    TNode* node = malloc(sizeof(*node));
    if (node == NULL) {
        return NULL;
    }

    node->value = value;
    node->left = NULL;
    node->right = NULL;
    return node;
}
```

Вызывающая функция должна проверить возвращённый указатель. В описании `CreateNode` нужно указать, что память переходит вызывающему коду и впоследствии должна быть освобождена.

Текст ответа и способ работы с ошибочным вводом определяются **условием лабораторной**. Не добавляйте в `stdout` приглашения «Введите число», отладочные сообщения или собственные формулировки ошибок, которых нет в условии. Диагностику для себя можно временно писать в `stderr`, но перед сдачей уберите отладочный вывод.

## 8. Комментарии объясняют смысл

Комментарии можно писать по-русски или по-английски. После `//` ставьте пробел.

Не пересказывайте очевидную операцию:

```c
// Увеличиваем i на один.
++i;
```

Полезнее объяснить причину или свойство алгоритма:

```c
// Правая граница не входит в рассматриваемый диапазон.
```

Перед публичной функцией в `.h` кратко укажите:

- что она делает;
- какие значения принимает и изменяет;
- что возвращает при успехе и ошибке;
- кто освобождает память, если функция её выделяет или принимает во владение.

Теги `@param` и `@return` допустимы, но не обязательны. Важнее содержание. У короткой функции описание может занимать две строки. Внутренний очевидный `Swap` не требует подробной документации каждого параметра.

Удаляйте закомментированные старые реализации, временные `printf` и устаревшие комментарии. Предыдущие варианты кода уже хранятся в Git.

## 9. Небольшой цельный пример

Ниже учебная программа, показывающая оформление трёх файлов. Она читает количество чисел от 1 до 100, затем сами числа и печатает максимум. Это пример организации кода; формат ввода и ответа своей лабораторной берите из её условия.

### `src/lib/array.h`

```c
#pragma once

#include <stdbool.h>
#include <stddef.h>

// Записывает максимум массива values из count элементов в result; массив не меняет.
// Возвращает false для пустого массива или NULL в values/result; result не изменяет.
bool FindMax(const int* values, size_t count, int* result);
```

### `src/lib/array.c`

```c
#include "array.h"

bool FindMax(const int* values, size_t count, int* result) {
    if (values == NULL || result == NULL || count == 0) {
        return false;
    }

    int maxValue = values[0];
    for (size_t i = 1; i < count; ++i) {
        if (values[i] > maxValue) {
            maxValue = values[i];
        }
    }

    *result = maxValue;
    return true;
}
```

### `src/main.c`

```c
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>

#include "lib/array.h"

#define MAX_VALUE_COUNT 100

static bool ReadValues(int* values, int count) {
    for (int i = 0; i < count; ++i) {
        if (scanf("%d", &values[i]) != 1) {
            return false;
        }
    }
    return true;
}

int main(void) {
    int count;
    if (scanf("%d", &count) != 1 || count < 1 || count > MAX_VALUE_COUNT) {
        printf("bad input\n");
        return EXIT_SUCCESS;
    }

    int values[MAX_VALUE_COUNT];
    if (!ReadValues(values, count)) {
        printf("bad input\n");
        return EXIT_SUCCESS;
    }

    int maxValue;
    if (!FindMax(values, (size_t)count, &maxValue)) {
        return EXIT_FAILURE;
    }

    printf("%d\n", maxValue);
    return EXIT_SUCCESS;
}
```

В `CMakeLists.txt` перечислите оба `.c` в существующем `set(SRC ...)`:

```cmake
set(SRC
    src/main.c
    src/lib/array.c
)
```

Остальные настройки шаблона, включая `include(common_lab)`, сохраняются. [Команды сборки и запуска тестов](how_to_cmake.md) описаны отдельно.

## 10. Что проверить перед сдачей

- [ ] Имена соответствуют таблице: функции `UpperCamelCase`, переменные и поля `lowerCamelCase`.
- [ ] Везде 4 пробела, единое расположение скобок и пробелов.
- [ ] У условий и циклов есть фигурные скобки, даже для одной строки.
- [ ] Названия объясняют смысл; ограничения задачи имеют имена.
- [ ] `main` организует работу, алгоритмы вынесены в модули.
- [ ] Публичные объявления находятся в `.h`, внутренние функции помечены `static`.
- [ ] Проверяются результаты чтения, выделения памяти и открытия файлов.
- [ ] Ресурсы освобождаются при обычном завершении и при ошибках.
- [ ] В ответе нет лишнего вывода, в исходниках нет отладочного мусора.
- [ ] Все `.c` добавлены в CMake; программа собирается и проходит проверки.

В CI используется `cppcheck`, но он не проверяет все договорённости этого документа: например, регистр имён, отступы и качество разбиения на функции. Эти вещи смотрит преподаватель при ревью. Автоформатирование редактора помогает с пробелами и скобками; после него проверяйте `git diff`, чтобы случайно не переформатировать всю работу в другом стиле.
