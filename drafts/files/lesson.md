# Чтение и запись файлов

{% include course-context.html %}

Стандартный ввод позволяет читать данные из терминала. Для работы
с конкретным файлом программа открывает отдельный **поток** — объект
стандартной библиотеки, через который идут операции чтения или записи.

## Полный цикл работы

Следующая программа создаёт файл `course-note.txt` в текущей папке,
записывает строку, закрывает файл, открывает для чтения и печатает содержимое.
Если файл с таким именем уже есть, режим `"w"` заменит его содержимое.
Для запуска удобно использовать отдельную папку с примером.

```c
{% include_relative examples/files.c %}
```

При успешной работе вывод — `Hello, file!`. Созданный файл остаётся
в папке после завершения программы.

`FILE` — тип из `<stdio.h>`, описывающий состояние потока. Мы работаем
с ним через `FILE*`, полученный от `fopen`. Детали устройства `FILE`
для обычного чтения и записи знать не нужно.

## Режим открытия

| Режим | Что происходит |
| --- | --- |
| `"r"` | Чтение существующего текстового файла |
| `"w"` | Запись: создание или очистка существующего файла |
| `"a"` | Запись в конец, создание при отсутствии |
| `"rb"`, `"wb"` | Чтение и запись в двоичном режиме |

В текстовом режиме библиотека может преобразовывать окончания строк.
Двоичный режим важен, когда требуется сохранить точные байты.
Текстовый режим сам по себе не выбирает кодировку текста.

`fopen` может вернуть `NULL`: например, файла нет, нет доступа или неверен путь.
Относительное имя ищется от текущей папки процесса, а не обязательно
рядом с исходником. При запуске из IDE текущая папка задаётся её настройками.

## Чтение до конца

`fgetc` возвращает очередной символ как значение `unsigned char`,
преобразованное в `int`, или специальное значение `EOF`.
Поэтому переменная `character` имеет тип `int`, а не `char`:
она должна различать все возможные байты и признак конца.

Условие `while ((character = fgetc(file)) != EOF)` сначала читает,
затем сравнивает результат. Дополнительные скобки подчёркивают присваивание.

`EOF` может означать как конец данных, так и ошибку. После цикла `ferror(file)`
помогает отличить ошибку чтения от нормального завершения.
Для построчного чтения можно использовать знакомый `fgets`, передав `file`
вместо `stdin`.

Не стоит писать `while (!feof(file))`: признак конца устанавливается
после попытки чтения, а не предсказывает её результат.

## Почему проверяется закрытие

Библиотека может накапливать записанные данные в буфере и отправлять их
позднее. Поэтому ошибка записи иногда обнаруживается только при `fclose`.
В примере проверяются и `fputs`, и закрытие выходного потока.

После `fclose` указатель больше не используется как открытый поток.
Его нельзя закрывать повторно или передавать в `fgetc`.
Поток закрывается и при раннем выходе после ошибки чтения или записи.

## Значения и байты

`fprintf(file, "%d\n", value)` пишет текстовую запись числа,
а `fscanf` разбирает текст. Для массивов байтов есть `fread` и `fwrite`;
они возвращают число полностью прочитанных или записанных элементов.

Записать структуру целиком через `fwrite` — ещё не определить переносимый
формат: размер типов, порядок байтов и заполнение между полями могут отличаться.
Для обмена данными нужно отдельно описывать формат и кодировать поля.
Эта тема подробно разобрана в статье о структурах.

Следующая глава вернётся к управлению выполнением: функция сможет вызывать
саму себя, сохраняя отдельные данные каждого вызова.
