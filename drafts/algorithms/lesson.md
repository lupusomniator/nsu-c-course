# Поиск, сортировка и сложность

{% include course-context.html %}

**Алгоритм** — определённый способ получить результат из исходных данных.
Одну задачу часто можно решить несколькими способами. Разница становится
заметной при росте числа элементов.

## Поиск последовательным просмотром

Пусть нужно узнать, есть ли число `7` в массиве. Самый прямой способ —
сравнить с ним каждый элемент и остановиться при совпадении.

В примере функция `Contains` возвращает `1`, если значение найдено, и `0` иначе.


В функции `Contains` может потребоваться до `count` сравнений.
Если элементов стало вдвое больше, максимальное число сравнений тоже
увеличится примерно вдвое.

## Что обозначает O(n)

Пусть `n` — число элементов. Запись **O(n)** описывает верхнюю оценку роста
затрат, пропорциональную `n`, при достаточно больших `n`.
Это не обещание точного числа миллисекунд и не обязательно точное число операций.

Для линейного поиска худший случай — нужного элемента нет или он последний.
Тогда время растёт как O(n). Если он первый, поиск заканчивается сразу.
Поэтому при сравнении алгоритмов важно говорить, какой случай рассматривается.

Дополнительная память функции поиска — несколько переменных, то есть O(1):
она не растёт с длиной массива. Память самого переданного массива здесь
не считается дополнительной.

## Двоичный поиск

Функция `ContainsSorted` требует массив, отсортированный по неубыванию.
В нашем примере это `1, 3, 5, 7, 9`.

Она хранит полуинтервал `[left, right)`: левый индекс входит в область поиска,
правый не входит. Изначально это весь массив: `[0, count)`.

Для поиска `7`:

| Область | Середина | Решение |
| --- | --- | --- |
| `[0, 5)` | Индекс 2, значение 5 | 7 больше: оставить `[3, 5)` |
| `[3, 5)` | Индекс 4, значение 9 | 7 меньше: оставить `[3, 4)` |
| `[3, 4)` | Индекс 3, значение 7 | Найдено |

Каждый шаг уменьшает область примерно вдвое. Поэтому число шагов растёт
как O(log n): для массива около миллиона элементов нужно порядка двадцати
делений пополам. Основание логарифма для этой записи оценки несущественно.

Формула `left + (right - left) / 2` избегает переполнения суммы `left + right`.
При `count == 0` тело вообще не выполняется: пустой массив обработан естественно.

## Почему сначала нужна сортировка

Если массив не отсортирован, сравнение с серединой не позволяет отбросить
половину элементов. Двоичный поиск может пропустить существующее значение.

Простой способ сортировки — **сортировка выбором**: найти минимум среди
необработанных элементов и поставить его на очередное место.

```c
void Sort(int* values, size_t count) {
    for (size_t i = 0; i < count; ++i) {
        size_t minimum = i;
        for (size_t j = i + 1; j < count; ++j) {
            if (values[j] < values[minimum]) {
                minimum = j;
            }
        }
        int temporary = values[i];
        values[i] = values[minimum];
        values[minimum] = temporary;
    }
}
```

После шага `i` первые `i + 1` элементов находятся на своих окончательных
местах. Вложенные обходы дают примерно `n * (n - 1) / 2` сравнений — O(n²).
Это понятный способ для небольших данных; существуют сортировки с оценкой
O(n log n), например сортировка слиянием.

Для одного поиска сортировать весь массив может быть дороже, чем просмотреть
его один раз. Для множества поисков по неизменному набору предварительная
сортировка может окупиться. Нужно учитывать все этапы, а не только последнюю функцию.

## Как проверить рассуждение

У поиска важны пустой массив, один элемент, первый и последний элементы,
отсутствующее значение и повторы. У сортировки — уже отсортированные данные,
обратный порядок и одинаковые значения. Эти случаи показывают ошибки
в границах и условиях, которые не видны на одном обычном примере.

Это введение в анализ алгоритмов. Для деревьев, графов и других структур
данных понадобятся отдельные главы с собственными способами хранения и обхода.
