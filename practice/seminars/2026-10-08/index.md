# 08.10.2026 — Области видимости и модули

Шесть задач на C17: область видимости, время хранения, связывание,
объявления и определения, заголовки, `const`, `enum`, `typedef` и `struct`.
Понадобятся базовые функции и указатели; динамическая память не нужна.
Работа рассчитана примерно на 65 минут плюс обсуждение.

| Задача | Тема | Время |
| --- | --- | --- |
| [A. Одна переменная или три?](A-scope/condition.md) | Scope, static, linkage | 5 мин |
| [B. Объявление или определение?](B-declarations/condition.md) | Объявления и определения | 5–7 мин |
| [C. Почини чужой модуль](C-repair-statistics/condition.md) | Компоновка и инкапсуляция | 10 мин |
| [D. Константа в заголовке](D-constants/condition.md) | const и ICE | 7–10 мин |
| [E. Библиотека статистики](E-statistics/condition.md) | Интерфейс и состояние модуля | 15 мин |
| [F. Дверь как конечный автомат](F-door/condition.md) | enum, struct, переходы | 20 мин |

Сначала сформулируйте ответ или план, затем запускайте код. A и B — короткие
упражнения на понимание. C и D содержат намеренно ошибочные файлы в `broken/`:
они запускаются отдельно по командам в условии и не входят в CMake-сборку.
E развивает модуль из C; F переносит состояние в отдельные объекты.

В каждой папке: `condition.md`, `explanation.md`, `main.c`, `solution.c`,
`CMakeLists.txt` и пары `tests/*.in` / `*.out`. Дополнительные реализации решения
лежат в `solution/`. Разборы и код скрыты под раскрывающимся блоком в условии.
Заготовки компилируются; до выполнения заданий B–F их тесты не проходят.
A уже содержит программу для исследования.

## Проверка

[Подготовка инструментов](../../../tasks.md). Из корня репозитория перейдите
в папку семинара. Windows: **Developer PowerShell for VS**.

```powershell
cd practice/seminars/2026-10-08
cmake -S . -B build -G "NMake Makefiles" -DCOURSE_USE_SOLUTIONS=OFF
if ($LASTEXITCODE -ne 0) { throw "Не удалось настроить сборку" }
cmake --build build
if ($LASTEXITCODE -ne 0) { throw "Исправьте ошибки компиляции" }
ctest --test-dir build --output-on-failure
```

<details markdown="1">
<summary>macOS / Linux</summary>

```sh
cd practice/seminars/2026-10-08
cmake -S . -B build -DCOURSE_USE_SOLUTIONS=OFF &&
cmake --build build &&
ctest --test-dir build --output-on-failure
```

</details>

Для готовых решений замените `build` на `build-solution` во всех командах,
а `-DCOURSE_USE_SOLUTIONS=OFF` на `-DCOURSE_USE_SOLUTIONS=ON`.
Для одной задачи сначала перейдите в её каталог и выполните те же команды
начиная с `cmake`. Не собирайте все `.c` одной маской: в дереве лежат разные
версии программ и намеренно ошибочные примеры.

`100% tests passed` означает совпадение результатов. Проверки не доказывают
инкапсуляцию, наличие `switch` и правильность объяснений — это проверяется по коду.
Сборка выбирает соответствующие заголовки и реализации автоматически;
исходные студенческие файлы при проверке решений не меняются.
