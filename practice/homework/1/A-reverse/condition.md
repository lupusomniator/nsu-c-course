# A. Лента из будущего

К фестивалю науки Маша нашла в лаборатории старый регистратор. Прибор целый день измерял что-то очень важное и печатал показания на длинной бумажной ленте. Что именно он измерял, уже никто не помнит, зато все уверены: выбрасывать результаты нельзя.

Сначала Маша переписала всю ленту в компьютер. И только потом лаборант вспомнил, что во время обеда принтер зажевал бумагу. Участок с позиции `l` до позиции `r` включительно прибор напечатал задом наперёд: последнее показание этого участка оказалось первым, предпоследнее — вторым, и так далее. С остальной лентой всё в порядке.

Лаборант уже собирается разрезать бумагу ножницами. Помогите Маше восстановить правильный порядок показаний раньше, чем он доберётся до единственного экземпляра.

## Формат ввода

В первой строке записано количество показаний `n`, `1 ≤ n ≤ 1000`.

Во второй строке записаны `n` целых чисел в том порядке, в котором Маша переписала их с ленты. Каждое число находится в диапазоне от −1000 до 1000.

В третьей строке записаны границы испорченного участка `l` и `r`, `0 ≤ l ≤ r < n`. Позиции на ленте нумеруются от 0 до `n - 1`.

## Формат вывода

Выведите все `n` показаний в исправленном порядке в одной строке, разделяя числа пробелами.

## Пример 1

Ввод:

```text
6
10 20 30 40 50 60
1 4
```

Вывод:

```text
10 50 40 30 20 60
```

## Пример 2

Ввод:

```text
1
7
0 0
```

Вывод:

```text
7
```

## Пример 3

Ввод:

```text
5
-3 0 5 8 1
0 4
```

Вывод:

```text
1 8 5 0 -3
```

### Проверить готовое решение — Windows

Один раз [установите инструменты и клонируйте репозиторий]({{ '/tasks/' | relative_url }}).
Откройте **Developer PowerShell for VS**. Из корня клонированного
`nsu-c-course` выполните:

```powershell
cd practice/homework/1/A-reverse
cmake -S . -B build-solution -G "NMake Makefiles" -DCOURSE_USE_SOLUTIONS=ON
if ($LASTEXITCODE -ne 0) { throw "Не удалось настроить сборку" }
cmake --build build-solution
if ($LASTEXITCODE -ne 0) { throw "Исправьте ошибки компиляции" }
ctest --test-dir build-solution --output-on-failure
```

Здесь собирается `solution.c`. Ваш `main.c` остаётся на месте, а результаты
сборки решения хранятся отдельно в `build-solution`.
`100% tests passed` означает успех; при ошибке показаны входной файл,
ожидаемый и полученный ответы. Тесты лежат в `tests/*.in` и `tests/*.out`.
Для проверки своего `main.c` используйте [общую инструкцию]({{ '/tasks/' | relative_url }}#как-проверять-решение).
