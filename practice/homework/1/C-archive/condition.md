# C. Архив привидений

Для стенда «Есть ли жизнь в подвале?» Маша оставила датчик в старой лаборатории на ночь. Утром он передал `n` показаний и разрядился. Значения бывают и положительными, и отрицательными; заведующий лабораторией утверждает, что это нормально, а организаторы фестиваля уже рисуют на афише привидение.

Теперь комиссия изучает запись. Один эксперт просит показание с самого конца, другой — с начала, третий хочет ещё раз проверить то, которое уже смотрели. Каждый называет номер записи, а Маша должна сообщить записанное под этим номером значение. Датчик включить заново не получится.

Помогите Маше ответить на все запросы в том порядке, в котором они поступили. Номера записей могут повторяться: комиссия очень любит перепроверять свои находки.

## Формат ввода

В первой строке записано количество показаний `n`, `1 ≤ n ≤ 1000`.

Во второй строке записаны `n` целых показаний датчика, каждое от −1000 до 1000. Записи пронумерованы от 0 до `n - 1` в порядке передачи.

В третьей строке записано количество запросов `q`, `1 ≤ q ≤ 1000`. В четвёртой строке записаны `q` номеров записей в порядке запросов. Каждый номер находится в диапазоне от 0 до `n - 1`.

## Формат вывода

Для каждого запроса выведите соответствующее показание датчика в отдельной строке. Всего должно получиться `q` строк.

## Пример 1

Ввод:

```text
6
12 -4 7 0 -8 25
5
5 0 2 5 1
```

Вывод:

```text
25
12
7
25
-4
```

## Пример 2

Ввод:

```text
1
7
3
0 0 0
```

Вывод:

```text
7
7
7
```

## Пример 3

Ввод:

```text
3
-1000 0 1000
3
2 1 0
```

Вывод:

```text
1000
0
-1000
```

### Проверить готовое решение — Windows

Один раз [установите инструменты и клонируйте репозиторий]({{ '/tasks/' | relative_url }}).
Откройте **Developer PowerShell for VS**. Из корня клонированного
`nsu-c-course` выполните:

```powershell
cd practice/homework/1/C-archive
cmake -S . -B build-solution -G "NMake Makefiles" -DCOURSE_USE_SOLUTIONS=ON
if ($LASTEXITCODE -ne 0) { throw "Не удалось настроить сборку" }
cmake --build build-solution
if ($LASTEXITCODE -ne 0) { throw "Исправьте ошибки компиляции" }
ctest --test-dir build-solution --output-on-failure
```

Здесь собирается `solution.c`. Ваш `main.c` остаётся на месте, а результаты
сборки решения хранятся отдельно в `build-solution`.
`100% tests passed` означает успех; при ошибке показаны входной файл,
ожидаемый и полученный ответы. Тесты лежат в `tests/*.in` и `tests/*.out`.
Для проверки своего `main.c` используйте [общую инструкцию]({{ '/tasks/' | relative_url }}#как-проверять-решение).
