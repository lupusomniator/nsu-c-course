# Публикация и обновление сайта

Документация собирается из Markdown в корне репозитория, в `materials/` и в `practice/`.
Главная страница — `README.md`, остальные страницы получают адреса из `permalink`
в начале файла. Оглавление: «Начало работы», «Задачи → Семинары / Домашки»,
«Материалы». Старые адреса `/git/`, `/ide/`, `/build-and-test/`, `/codestyle/`
сохранены.

Ожидаемый адрес: https://lupusomniator.github.io/nsu-c-course/

## Первое включение GitHub Pages

1. Войдите в GitHub под аккаунтом с правом управления репозиторием.
2. Откройте [Settings → Pages](https://github.com/lupusomniator/nsu-c-course/settings/pages).
3. В **Build and deployment → Source** выберите **GitHub Actions**.
4. Отправьте подготовленные коммиты в `main`.
5. Во вкладке [Actions](https://github.com/lupusomniator/nsu-c-course/actions)
   дождитесь успешного workflow **Documentation site**: сначала `build`, затем `deploy`.

Если коммиты уже отправлены до включения Pages, откройте этот workflow и нажмите
**Run workflow → main → Run workflow**. Если среда `github-pages` требует
ручного одобрения, GitHub покажет кнопку **Review deployments**.

Для отправки через GitHub CLI можно настроить вход так:

```bash
gh auth login --hostname github.com --git-protocol https --web --scopes workflow
gh auth setup-git
git push origin main
```

Разрешение `workflow` нужно для отправки файла `.github/workflows/pages.yml`.
Персональный токен в файлы репозитория или настройки workflow добавлять не нужно:
сборка использует автоматический `GITHUB_TOKEN` с разрешениями на публикацию Pages.

## Как обновлять материалы

1. Отредактируйте нужный `.md`.
2. Сохраните изменения в коммит и отправьте их в `main`.
3. GitHub Actions соберёт и опубликует новую версию.

Для pull request выполняются сборка и проверка ссылок. Публикация выполняется
только из `main`. Не отправляйте `_site/`, `vendor/` и `.bundle/`: они исключены
через `.gitignore`.

Также запускается проверка задач на Windows и Linux. Публикация ждёт успешного
завершения обеих проверок и сборки сайта.

## Теоретические материалы

`materials.md` — главная страница раздела с оглавлением и командами запуска.
Тексты расположены в `materials/`, самостоятельные программы —
в `materials/examples/`. Теория организована по темам, а не по датам занятий:
один материал можно использовать на нескольких семинарах.

У каждой страницы есть `parent: Материалы`, `nav_order` и постоянный адрес
`/materials/<topic>/`. Главная страница раздела имеет `has_children: true`.
Названия файлов могут отличаться от адресов: ссылки между текстами пишутся
на `.md`, и Jekyll преобразует их в нужные URL. Примеры `.c` публикуются
как обычные файлы для просмотра и скачивания; на сайте они не исполняются.
Ссылки на `.c` задавайте через `relative_url`, например
`[Пример]({{ '/materials/examples/structBasics.c' | relative_url }})`:
это учитывает базовый путь сайта и не привязывает файл к `permalink` статьи.

При добавлении темы создайте `materials/<topic>.md`, добавьте её в таблицу
`materials.md` и, если есть запускаемые примеры, сохраните их в
`materials/examples/`. В каждом самостоятельном примере свой `main`;
особенности платформ и компилятора указывайте в материале и таблице примеров.
Проверьте сборку сайта и ссылки командами из раздела «Локальный просмотр».

Материалы от 15.10.2026 перенесены из `seminars/15.10.2026/materials/`
вне репозитория. Дальнейшие изменения опубликованной версии вносите здесь;
исходная папка семинара сохранена как архив и не участвует в сборке.

## Задачи семинаров и домашек

Материалы занятия 24.09.2026 находятся в `practice/seminars/2026-09-24/`.
Это основное место для дальнейшего редактирования опубликованных задач.
Исходная папка занятия вне этого репозитория сохранена как архив и не участвует
в сборке сайта.

В каждой папке задачи:

- `condition.md` — страница с условием и командами для Windows и macOS/Linux;
- `explanation.md` — разбор алгоритма, граничных случаев и сложности;
- `main.c` — пустая заготовка для студента;
- `solution.c` — полное проверенное решение;
- `tests/*.in` и `tests/*.out` — входы и ожидаемые ответы;
- `CMakeLists.txt` — самостоятельный CMake-проект.

В `condition.md` разбор и код подключаются через `include_relative` прямо
из `explanation.md` и `solution.c`. Копии кода в Markdown поддерживать не нужно.
На GitHub эти файлы можно открыть отдельно; блоки с подключениями разворачиваются
при сборке сайта. Дополнительный генератор страниц и ZIP-архивы не используются.

Условия имеют `parent` с точным названием семинара и постоянный адрес вида
`/tasks/seminars/2026-09-24/A-middle/`. Иерархия меню задаётся заголовками и `parent`,
независимо от папок; [правила темы Just the Docs](https://just-the-docs.com/docs/navigation/main/).

Чтобы добавить семинар, создайте папку `practice/seminars/YYYY-MM-DD/`, страницу
`index.md` с `parent: Семинары`, общий `CMakeLists.txt` и папки задач по образцу.
Обновите таблицу в `practice/seminars/index.md`. Для домашки используйте
`practice/homework/<id>/` и `parent: Домашки` у её страницы. Разбор и решение нужны
для каждой опубликованной задачи. Теорию добавляйте страницами с `parent: Материалы`.

Домашка #0 находится в `practice/homework/0/`. Условия и 300 пар тестов перенесены
из `homeworks_new/c_basics_contest/problems` без изменения содержимого тестовых
файлов; первые три теста каждой задачи переименованы в `01_example`–`03_example`.

Общие правила сборки и проверки находятся в `practice/cmake/`.
Режим `tokens` сравнивает элементы ответа, `line` допускает отсутствие последнего
перевода строки, `exact` сохраняет все пробелы и переводы строк. LF и CRLF
равнозначны во всех режимах. Для `float` автоматически собирается
`CompareFloat.c`: он проверяет одно конечное число с абсолютной погрешностью
`0.0001`. Граничные случаи этого проверяющего модуля входят в `check_practice.py --build`.
По умолчанию компилируется `main.c`; `-DCOURSE_USE_SOLUTIONS=ON` выбирает
`solution.c`. Используйте разные папки сборки для этих режимов.
Тестовые файлы отмечены в `.gitattributes` как `-text`, чтобы Git на Windows
сохранял точные байты тестов, включая пробелы и отсутствие последнего перевода строки.

Проверка материалов без компиляции:

```sh
python3 scripts/check_practice.py
```

Полная проверка (на Windows команда Python обычно называется `python`):

```sh
python3 scripts/check_practice.py --build
```

Скрипт проверяет пары входов и ответов, соответствие примеров тестам и наличие
разборов; собирает все заготовки, проверяет решения как общий проект занятия
и каждую задачу как самостоятельный проект. Сборки создаются во временной папке
и удаляются после проверки. Пустые заготовки не должны проходить тесты.

Файлы сборки и тесты не копируются в сайт: студенты получают их через `git clone`.
Не добавляйте сгенерированные `build*` и `cmake-build-*` в репозиторий.

Чтобы добавить страницу, создайте Markdown-файл с заголовком настроек:

```yaml
---
title: Название раздела
nav_order: 7
permalink: /new-section/
---
```

После него пишите обычный Markdown. `nav_order` задаёт место в меню, `permalink`
— постоянный адрес. В ссылках между документами используйте имена `.md`, например
`[Сборка](how_to_cmake.md)`: плагин преобразует их в адреса страниц сайта.

При переименовании заголовка проверяйте ссылки с `#раздел`: автоматическая проверка
останавливает сборку, если раздел или локальный файл отсутствует.

## Локальный просмотр

Нужны Ruby версии из `.ruby-version`, Bundler и Python 3.9 или новее.
Из корня репозитория:

```bash
bundle config set --local path vendor/bundle
bundle install
bundle exec jekyll serve --host 127.0.0.1
```

Откройте http://127.0.0.1:4000/nsu-c-course/.

Проверка перед отправкой:

```bash
bundle exec jekyll build --strict_front_matter
python3 scripts/check_site.py _site /nsu-c-course
```

`Gemfile.lock` фиксирует версии зависимостей для локальной сборки и CI. После
осознанного обновления зависимостей включайте его изменения в коммит.

## Если публикация не прошла

- Ошибка в `build`: откройте журнал; исправьте Markdown, ссылки или зависимости.
- Ошибка в `deploy`, связанная с Pages: проверьте источник **GitHub Actions**
  в Settings → Pages и права workflow / правила среды `github-pages`.
- `git push` отклонён: проверьте аккаунт и права на репозиторий. Не используйте
  `--force`; если `main` изменился на сервере, сначала согласуйте локальную историю.

Настройки сайта находятся в `_config.yml`. Если изменятся владелец или название
репозитория, обновите `url`, `baseurl`, ссылки на GitHub и аргумент базового пути
в `.github/workflows/pages.yml`.

Этот файл служит памяткой для преподавателя и исключён из публикуемого сайта.
